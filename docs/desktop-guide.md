# rauha 데스크톱 사용 안내 (한 장)

처음 쓰는 사람을 위한 안내예요. 확인하지 못한 것은 "확인 못 함"이라고 적었어요.

## 1. 설치

설치 파일은 GitHub Releases에서 로그인 없이 받아요: https://github.com/kimvudghk11/rauha/releases (README의 "바로 내려받기" 링크도 같아요). 파일 배치와 빌드 방법은 `packages/desktop/PACKAGING.md`에 있어요.

**맥북(macOS)**
1. `rauha-…-mac-arm64.dmg`(Apple 칩, M1 이상)나 `rauha-…-mac-x64.dmg`(인텔) 중 내 맥에 맞는 것을 받아 열어요(Apple 메뉴 → 이 Mac에 관하여에서 칩을 볼 수 있어요).
2. 열리는 창에서 rauha 아이콘을 Applications 폴더로 끌어다 놓아요.
3. 처음 열면 **"Apple은 rauha에 … 악성 코드가 없음을 확인할 수 없습니다"** 경고가 떠요. 서명이 없는 앱이라 나오는 정상 경고예요(고장이 아니에요). 아래 둘 중 하나로 열어요. (이 경고는 **처음 설치할 때 한 번**만이에요. 앱을 연 뒤 설정 → 새 버전의 **지금 업데이트**로 받은 새 버전에는 같은 경고가 뜨지 않아요. 앱이 직접 받은 파일은 브라우저가 붙이는 "인터넷에서 받음" 표시가 없기 때문이에요.)
   - **터미널 한 줄(가장 빠름)**: `xattr -dr com.apple.quarantine /Applications/Rauha.app` 을 실행하고 앱을 다시 열어요.
   - **시스템 설정**: 앱을 한 번 열어 경고에서 **완료**를 눌러요. 그다음 시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 "rauha가 차단되었습니다" 옆 **그래도 열기** → 암호나 Touch ID → **열기**. macOS 15(Sequoia)부터는 예전의 "우클릭 → 열기"가 통하지 않아요.
4. 회사 보안 소프트웨어가 막으면 아래 "소스로 실행하기"로 가요.

**Windows**
`rauha-Setup-…-x64.exe`를 받아 실행해요. 서명이 없어서 "알 수 없는 게시자" 경고가 뜨면 "추가 정보 → 실행"을 눌러요.

## 2. 처음 열면

- **권한 허용**: 알림 권한을 물으면 허용해요(허락이 필요할 때 알려 줘요). 맥은 문서·데스크톱 폴더에 처음 접근할 때 묻는 창이 뜨면 허용해요. 알림이 안 보이면 시스템 설정 → 알림에서 rauha를 켜요.
- **첫 실행 안내(3단계)**: ① 일할 **작업 폴더**를 골라요(레포와 문서 폴더가 들어 있는 폴더 하나) → ② 그 폴더에서 일해도 되는지 **허락** → ③ 쓸 **Claude 계정** 고르기(모르면 "폴더 규칙에 맡기기"). 폴더를 고르고 허락하기 전에는 일을 맡길 수 없어요.
- **예전 터미널 rauha**가 PC에 있으면 "지울까요?" 창이 떠요. 어떤 파일을 지우는지 보여 주고, "지우기"를 눌러야만 지워요. 기억·학습 노트·대화 기록은 그대로예요. 모르겠으면 "그대로 두기".

## 3. Claude 로그인 (안 돼 있을 때)

rauha는 Claude 구독 로그인을 그대로 써요. 토큰은 읽지도 옮기지도 않아요. 일을 맡겼는데 "로그인되어 있지 않거나 만료됐어요"라고 나오면 터미널에서 Claude Code로 로그인해요: `claude auth login` (계정을 나눠 쓰면 그 계정의 설정 폴더로). 로그인한 뒤 앱에서 다시 맡겨요.

## 4. 일 맡기기

- 아래 입력창에 쓰고 **Enter**(줄바꿈은 Shift+Enter). 보낸 뒤에도 바로 다음 일을 보낼 수 있어요. 동시에 3개까지 돌고(설정에서 바꿔요, 다음 실행부터 적용) 넘치면 "대기"예요.
- **`@폴더이름`**을 맨 앞에 쓰면 그 레포·폴더에서 일해요. 예: `@api-server 결제 타임아웃 원인 찾아줘`. 이름은 코드 탭 탐색기의 레포 줄에서 볼 수 있어요.
- **`/명령`**(명령어 탭): 입력창에 `/`를 치면 명령 목록이 자동완성으로 떠요(↑↓ 고르기, Tab으로 채우기, Enter로 보내기, Esc 닫기). 터미널판 rauha의 슬래시 명령이 **기본 명령**으로 처음부터 들어 있어요. 명령어 탭에서 이름·설명·하는 일·인자를 볼 수 있고, 기본 명령은 끄거나("기본 명령 되돌리기"로 한꺼번에 켜요), **내 명령**(이름 + 프롬프트 템플릿 + 인자 `{{x}}`)을 더하고 고치고 지울 수 있어요. 인자는 `{{요청}}`(꼭 채움), `{{브랜치|main}}`(안 채우면 main)처럼 적고, 마지막 인자는 남은 글 전부를 받아요. 명령이 아닌 글을 `/`로 시작해 보내려면 `//`로 시작해요.
  - 팀에 일을 맡기는 명령: `/review [브랜치]`(변경 리뷰, 파일은 안 고침), `/design <요청>`(설계부터), `/learn [범위]`(패턴 복습), `/company`(부서별 정한 것 요약), `/개선 <대상> <요청>`(= `/improve`).
  - 앱이 바로 하는 명령(모델을 안 불러요): `/repo`(코드 탭의 레포 목록), `/routine`(할 일 탭), `/team`(설정의 팀 설정), `/clear`(채팅 화면 비우기, 돌고 있는 작업은 그대로), `/status`, `/queue`, `/usage`(%만), `/guide`(지난 작업 정리 열기), `/copy`(마지막 답 복사), `/진단`(진단 정보 복사), `/retry`(마지막 요청 다시), `/help`, `/exit`(창 닫기).
  - `/설치`(= `/install`): 이 컴퓨터에 맞는 설치 방법. 맥은 `curl -fsSL https://raw.githubusercontent.com/kimvudghk11/rauha/main/scripts/install-mac.sh | bash` 한 줄을 **복사 버튼**으로 줘요(브라우저로 받지 않아서 첫 실행 경고가 안 떠요). Windows는 최신 설치 파일 내려받기 버튼이에요.
  - `/업데이트`(= `/update`): 새 버전이 있는지 확인하고 같은 방법을 보여줘요.
  - `/개선 <대상> <요청>`: 업데이트 요청이 올 때 쓰는 3단계예요. ① 공격적 점검(약점 분석·부족한 기능·보안·모의 해킹 관점의 취약점 탐색, 읽기 중심, 파괴 동작은 안 해요, 내 소유 프로젝트만) ② 그 결과를 근거로 개선 ③ 추가 테스트와 마무리. 한 작업으로 올라가 팀 방에서 진행이 보이고, 각 단계 결과가 다음 단계 입력이 돼요. 허락 카드와 규칙(비밀 파일·push 금지)은 그대로예요.
  - 터미널판의 `!명령`(모델 없이 바로 실행)은 앱에는 옮기지 않았어요.
- 질문에는 보통 빨리 가볍게 답하고, 답 아래 **"더 깊게"** 를 누르면 같은 질문을 깊게 다시 답해요. 저장소 정보를 아직 못 읽은 채 답했으면 그 답 카드 안에 "저장소 정보를 아직 못 읽었어요"라고 나와요.
- 일 카드의 **멈추기**로 언제든 멈출 수 있어요.

## 5. 팀 방과 허락 카드

- 일이 시작되면 오른쪽에 **팀 방**이 생겨요. 캐릭터(팀원), 진행 단계 막대, 마지막 한 줄, 걸린 시간이 보이고, 끝나면 잠시 뒤 사라져요. 방을 누르면 **팀 상세**가 열려요(기본은 "정리", "원본 로그" 탭에서 원본을 봐요).
- 팀이 위험한 일을 하려면 **허락 카드**가 떠요(오른쪽 아래 알림과 Windows·맥 알림). 읽는 법:
  - 맨 위 한 줄: 무슨 일인지(예: "main 브랜치에 push")와 요청한 팀원.
  - **코드**: 보호 브랜치(main·qa·release …)에 주는 영향 표 — 앞선/뒤처진 커밋 수, 충돌 여부, 자동 배포 여부 — 와 바뀐 파일, "diff 보기".
  - **인프라**: 환경(운영 여부), 계정·리전, 영향 범위, 중단 여부, 비용 방향(늘어남·줄어듦·같음만, 금액은 안 보여요), 되돌리는 시간, qa에 먼저 적용했는지. 알 수 없는 칸은 **"모름"** 이에요(지어내지 않아요). "원본 명령"도 펼쳐 볼 수 있어요.
  - 버튼: **한 번만 허락** / **이번 작업 동안 허락** / **다르게 해 줘**(말로 고쳐서 보내요) / **거절**.
- 비밀 파일(`.env` 등) 읽기·쓰기와 `git push`는 허락 카드와 상관없이 막혀 있어요(규칙으로도 풀 수 없어요).
- 같은 레포에 일이 둘 이상 돌면 두 번째부터는 따로 복사한 작업 폴더(worktree)에서 일하고, 끝나면 고친 내용을 `rauha/job-…` 브랜치로 남겨요. 합치는 것은 허락 카드를 거쳐요.

## 5-1. 분석: 조사 → 방향 비교 → 설계 → 계획 → 고치기

"결제가 왜 두 번 깎여?", "이 에러 원인 분석해줘", "어떻게 고치는 게 좋을지 방향 비교해줘", "분석하고 고치는 계획까지 짜줘"처럼 **분석·조사·비교를 청하면** 팀이 단계별로 일해요. 단순한 수정 요청("오타 고쳐줘")과 가벼운 질문은 이 흐름을 타지 않아요.

1. **조사**: 확인한 사실(근거 파일 필수), 원인 후보(확신도), 아직 모르는 것. "원인이 뭐야"만 물으면 여기서 끝나요(호출 1번).
2. **방향 비교**: 고치는 방향 2~4개를 장점·단점·위험·되돌리기 쉬움·손댈 곳으로 비교하고, **AI 추천 하나**를 표시해요. 팀 상세의 **질문 카드**가 뜨면 추천을 그대로 고르거나, 다른 방향을 고르거나, **직접 쓴 방향**을 보낼 수 있어요(이유 한 줄은 선택). 이 선택은 **기록 탭의 "방향" 칸**에 남고, AI 추천과 다르게 골랐으면 표시돼요.
3. **설계 + 4. 단계별 계획**: 고른 방향의 목표·비목표·바뀌는 지점·데이터 흐름·엣지 케이스·버린 안·테스트 전략과, 단계마다 먼저 쓸 테스트·바꿀 파일·확인 명령이 나와요. 설계 모델은 기본 sonnet, 큰 변경(영역 셋 이상·여러 저장소)만 opus예요.
5. **승인**: 카드에서 **이대로 고치기**를 누르면 그 계획이 그대로 기존 테스트 먼저(BDD/TDD) 작업의 입력이 돼요. **고칠 점 적고 다시**는 설계·계획을 다시 쓰게 하고(3번까지), **여기서 멈추기**는 거기서 끝내요.

문서는 작업 폴더의 `docs/analysis/날짜-주제.md`(레포에 `docs/analyses` 같은 폴더가 이미 있으면 거기)에 **단계마다 이어 써요**. 이미 있는 파일은 덮어쓰지 않고 `-2`, `-3`을 붙여요. 도중에 멈춰도 거기까지는 남아요. 문서는 새 파일이라 커밋하기 전까지는 "커밋 안 한 변경"이에요(승인한 구현은 이 문서를 알고 있어서 거절되지 않아요).

멈추는 경우(모두 문서는 남아요)
- 카드에 30분 동안 답이 없으면 카드를 닫고 그 단계에서 멈춰요. 추천대로 **자동으로 진행하지 않아요**(한도를 쓰지 않으려고).
- 작업을 멈추거나, 한도·로그인 문제로 팀원 호출이 막히면 그 단계에서 멈추고 이유를 알려요.
- 한도가 90%를 넘으면 조사까지만 하고, 카드를 기다리는 사이 90%를 넘으면 설계로 가지 않아요. 70% 이상이면 큰 변경이어도 opus를 쓰지 않아요.

설정 → **분석 → 분석 단계 쓰기**를 끄면 분석은 예전처럼 팀원 한 번 호출이에요(질문 카드도 안 나와요). 다음 요청부터 적용돼요. 호출 수는 최대 3번(조사·방향 비교·설계와 계획)이고, 조사에서 멈추면 1번이에요.

## 6. 규칙 탭

내 규칙을 칸 셋으로 나눠 적어요: **항상 지킬 것**(팀원에게 늘 알려 줘요) / **묻지 않고 할 것** / **꼭 허락받을 것**. 범위는 전체·작업 폴더·특정 폴더예요.

- **말로 적기**: 한 문장으로 적고 "정리하기"를 누르면 가장 가벼운 모델을 한 번 불러 칸·범위·찾을 글을 정리해 아래 칸에 채워 줘요. 확인하고 고친 뒤 "규칙 더하기"를 눌러야 들어가요(모델 호출 1번).
- **기본 규칙**: 규칙 탭에는 rauha를 만들며 정한 규칙이 "기본" 표시로 처음부터 들어 있어요. 항상 지킬 것(비밀 파일 읽기·쓰기 금지, 화면에 달러 금액 쓰지 않기, 확인 못 한 값은 "모름"으로 쓰기, aws 점검은 aws configure 프로필로 바로 실행), 묻지 않고 할 것(기본 git 읽기·준비, aws 조회, 테스트·타입 검사·빌드, 브라우저·claude 연동 확인), 꼭 허락받을 것(main·qa·release 보호 브랜치 push·merge, 운영 인프라 변경·삭제·비용이 느는 일). 카드마다 **켬/끔**, **고치기**(글과 찾을 글), **기본값으로**가 있고 아래 "기본 규칙 모두 되돌리기"로 한꺼번에 처음 상태로 돌려요.
  - 기본 규칙을 꺼도 비밀 파일 차단과 팀원의 `git push` 거절은 규칙보다 먼저 늘 지켜져요(카드에 작게 적혀 있어요). "묻지 않고 할 것" 기본 규칙은 앱이 이미 허용하는 명령만 담아서, 앱이 묻는 명령(예: git reset)을 풀어 주지 않아요.
  - 여러 명령을 이은 글(`a && b`)은 "묻지 않고 할 것" 규칙으로 통째로 풀리지 않아요. 맞는 한 조각 때문에 위험한 다른 조각이 묻지 않고 지나가면 안 되니까요.
- "묻지 않고/꼭 허락받을 것"은 **찾을 글**(명령이나 경로에 들어 있는 글, 예: `terraform apply`)로 판정해요. 둘 다 맞으면 "꼭 허락받을 것"이 먼저예요.

## 6-1. 할 일 탭과 기록 탭

- **할 일 탭**: 노션식 칸반 보드예요. AI와 상관없는 일도 그냥 적어 두고 관리할 수 있어요(AI에 맡기는 건 선택).
  - **끌어서 놓기**: 카드를 마우스로 끌어 다른 칸으로 옮기거나 칸 안에서 순서를 바꿔요(놓을 자리에 파란 선이 떠요). 숨긴 칸 위에 놓아도 그 칸으로 옮겨져요. 순서는 저장돼서 다시 켜도 그대로예요. 칸 머리를 끌면 칸 순서도 바뀌어요. 키보드로는 카드에 초점을 두고 **방향키**로 카드 사이를 오가고, **Alt+방향키**로 카드를 위·아래·옆 칸으로 옮겨요. **Enter**는 카드 열기, **n**은 새 카드(초점 카드가 있는 칸, 없으면 첫 칸)예요.
  - **칸**: 칸은 폭 272px로 고정이고 칸이 많으면 가로로 스크롤해요(창이 좁아도 칸 선택 탭으로 바뀌지 않아요). 기본은 "할 일 / 진행 중 / 완료"예요. 오른쪽 끝의 "+ 칸 추가"로 더하고, 칸 머리의 색 칩 이름을 두 번 누르거나 **⋯ 메뉴**에서 이름 바꾸기·색·완료로 취급·접기·**숨기기**·앞뒤로 이동·지우기를 해요. 머리에는 카드 수가 보이고 **+** 는 그 칸 맨 위에 새 카드를 넣어요. 숨긴 칸은 오른쪽 끝 "숨긴 칸" 영역에서 **보이기**로 되살려요(보이는 칸은 하나 이상 있어야 해요). **완료로 취급**을 켠 칸(기본은 "완료")에 있는 카드는 끝난 것으로 봐서 기한 지남 표시가 없고, **팀이 일하는 칸**(기본은 "진행 중")은 팀에 맡기면 카드가 가는 칸이에요. 칸을 지울 때 카드가 있으면 **옮길 칸을 골라** 옮기거나 카드까지 함께 지울 수 있고, 함께 지우는 건 되돌릴 수 없다고 먼저 알려요. 칸은 12개까지예요.
  - **카드**: 칸 아래 "+ 새로 만들기"에 제목만 치고 Enter를 누르면 바로 만들어지고, 입력칸이 그대로 남아 이어서 쓸 수 있어요(Esc로 끝). 카드에는 제목과 값이 있는 속성(라벨·우선순위·마감·레포·팀·체크리스트 진행)만 칩으로 보여요. 카드를 누르면 화면 가운데에 **카드 창(모달, 폭 720px)**이 열려서 큰 제목과 `이름 : 값` 속성 표(칸·우선순위·마감일·레포·맡길 팀·**라벨**, 8개까지), 글에 맞춰 높이가 늘어나는 **설명**, **체크리스트**(Enter로 잇따라 추가, 항목 안에서 Alt+위/아래로 순서 바꾸기, 진행률 막대, 50개까지)를 고쳐요. **Esc**·바깥 누르기·**×**로 닫고, 닫는 순간 아직 안 보낸 고침도 바로 저장돼요. 평소에는 고치는 즉시 **자동 저장**돼요(글은 입력을 잠깐 멈추면). 카드를 **오른쪽 클릭**(또는 ContextMenu 키)하면 열기·**복제**·칸 이동·위/아래·팀에 맡기기·지우기 메뉴가 떠요. 마감이 지난 카드는 빨갛게 보여요.
  - **보기**: 위쪽에서 검색(제목·설명·라벨·체크리스트)과 라벨·우선순위·레포·"기한 지난 것만"으로 걸러요. **보드 / 목록** 단추로 같은 데이터를 칸반이나 표로 봐요(목록에서는 보드 순서·우선순위순·마감순·최신순으로 정렬해요). 목록에서 줄을 눌러도 같은 카드 창이 열려요.
  - **팀에 맡기기**: 카드 창이나 우클릭 메뉴의 버튼을 누르면 `@레포 제목`·설명·체크리스트가 메인으로 가고 카드는 "팀이 일하는 칸"으로 가요. 작업이 끝나면 완료로 취급하는 칸으로, 멈추면 첫 칸으로 돌아와요(그 사이 직접 옮겨 둔 카드는 건드리지 않아요). 앱을 껐다 켜면 살아 있지 않은 작업에 매인 카드는 첫 칸으로 돌아와요.
  - **채팅에서 담기**: 메인에서 보낸 일 카드의 "할 일로 담기"를 누르면 그 일이 첫 칸에 카드로 저장돼요.
  - 저장은 이 PC의 `~/.rauha/desktop/todos.json`이에요. 예전 버전(세 칸 고정) 파일은 열 때 새 구조로 바뀌고 **원본은 `todos.json.bak-시각`으로 남아요**. 파일이 깨지면 `.broken-시각` 복사본을 남기고 열어요.
- **기록 탭**: 끝난 작업(끝남·멈춤)마다 요약이 자동으로 쌓여요: 요청, 일한 팀원, 거친 단계, 시작·끝 시각과 걸린 시간, 결과 요약, 바뀐 파일, 허락 결정과 이유. 방향을 고를 일에서 AI 추천과 다르게 골랐거나 허락 때 "다르게 해 줘"라고 했으면 "내가 다르게 골랐어요"가 붙어요.
  - 태그(트러블슈팅·네트워크 구성·인프라·설계·기능 구현·보안·성능·문서·기타)는 요청 글로 어림해 붙이고, 눌러서 바꿀 수 있어요. 검색과 태그·상태·레포·기간·"다르게 골랐어요" 필터가 있어요.
  - "마크다운으로 복사"는 문제 → 접근 → 방향 → 결과 순서로 포트폴리오·이력서에 옮겨 쓰기 좋게 뽑아요. 메모칸에 면접에서 말할 것을 적어 둘 수 있어요.
  - **요약만 남아요**: 토큰·키·비밀번호 모양의 값, 코드 블록, 전체 로그, 달러 금액, `.env`·키 파일 이름은 기록에 넣지 않아요(결과는 12줄·600자까지). 앱이 꺼진 사이에 끝난 작업은 기록되지 않아요.
  - **목록 쓰기**: 줄마다 끝남/멈춤·태그·시각·걸린 시간이 보여요. ↑↓로 줄을 옮기고 Enter로 열고 Esc로 목록으로 돌아가요. 줄 앞 체크 칸(Shift+클릭은 범위, 키보드는 x)으로 여러 개를 골라 위 작업줄에서 "3개 선택" 확인 후 블로그 글·복사·삭제를 한꺼번에 해요. 지우기는 항상 확인 창이 떠서 몇 개를 지우는지 보여 주고, 되돌릴 수 없어요. 조건을 걸면 "필터 지우기"가 나타나고 검색칸의 ×로 검색어를 지워요.
  - **상세 위쪽 줄**: 목록으로 · 블로그 글 · 복사(파랑) · 지우기(빨강)가 스크롤해도 맨 위에 붙어 있어요. 태그 칩(▾)을 누르면 메뉴에서 켜고 꺼요. 복사하면 "복사했어요" 알림이 잠깐 떠요.
  - 저장은 `~/.rauha/desktop/records.json`이에요(2000개가 넘으면 오래된 것은 지우지 않고 `records.json.archive.jsonl`로 옮겨요). AWS(S3) 전송은 아직 없어요.

### 트러블슈팅 블로그 글 (기록 탭)

겪은 문제를 블로그에 올릴 글로 정리해 줘요. 포트폴리오용 요약과는 따로, **공개해도 되게 가린 글**을 만들어요.

1. **고르기**: 기록을 하나 열고 "블로그 글"을 누르거나, 목록에서 여러 개를 체크하고 위 작업줄의 "블로그 글"을 눌러요. 기록이 없으면 "글감이 없어요"라고 알려요.
2. **정리 노트(모델을 부르지 않아요)**: 기록의 요청·단계·허락 결정(막힌 것 포함)·결과·바뀐 파일·메모로 `문제 상황 / 원인 추정 / 시도한 것(실패 포함) / 해결 / 배운 점 / 재현·확인 방법` 칸을 채워요. 기록에 근거가 없는 칸은 지어내지 않고 "직접 채우기"로 남겨요. 글 길이를 고르면 들어가는 칸이 달라져요: 짧게(문제·해결·배운 점), 보통(+원인·시도), 자세히(+재현·확인, 바뀐 파일). 제목 후보 3개와 태그 후보 3개를 함께 보여 줘요.
3. **공개용 가림(항상 켜져 있어요)**: 작업 폴더의 레포·폴더 이름, 기록에 적힌 레포 이름, 설정에 적은 회사·서비스 이름("가릴 이름" 칸에 한 줄에 하나씩, 설정에 저장돼요)은 "서비스 A", "레포 A"로 바뀌어요. 도메인, IP, 12자리 계정 번호, 리전, ARN, 이메일, 사용자 이름·홈 경로, 달러 금액도 가려요. 토큰·키와 비밀 파일(.env 등) 이름·경로는 아예 글에 넣지 않아요.
   - "바뀐 목록"에서 원래 → 바뀐 이름을 보고, 항목마다 "되돌리기"로 그대로 쓸 수 있어요(이름·도메인·IP 같은 것만. 키·토큰·비밀 파일·금액은 되돌릴 수 없어요).
   - 코드 조각은 기본으로 들어가지 않아요. 직접 붙여 넣고 "글에 넣기"를 체크한 것만 들어가요(비밀 파일 이름이나 환경 변수 파일 모양이면 막아요).
4. **초안 쓰기(모델을 한 번 불러요)**: 어투(담백/친근)를 고르고 "초안 쓰기"를 누르면 먼저 "모델을 한 번 부릅니다"를 보여 줘요. "초안 쓰기 시작"을 눌러야 실행돼요. 문서 팀원(잉크)이 가장 가벼운 모델(haiku)로, 도구 없이, 가린 정리 노트만 읽고 글만 돌려줘요(파일은 만들지 않아요). 구독 한도를 조금 써요. 모델이 쓴 글이라 사실과 다를 수 있으니 올리기 전에 꼭 읽어 보세요.
5. **내보내기**: "정리 노트 복사"·"초안 복사"(클립보드), ".md로 저장"(저장 대화상자에서 폴더를 직접 골라요. 작업 폴더 밖도 되고, 같은 이름이 있으면 덮어쓰기 전에 물어봐요).

## 7. 코드 탭 (레포 목록 · 파일 조작 포함)

VS Code를 열지 않고 파일을 보고 고치는 곳이에요. 왼쪽 탐색기, 위쪽 파일 탭, 아래 터미널 칸으로 되어 있어요.

- **작업 폴더 → 레포들**: 탐색기 맨 위가 작업 폴더이고, 그 아래 레포·문서 폴더가 최상위 노드로 보여요. 줄에는 진짜 폴더 이름만 보이고 상태 글은 붙지 않아요. 커밋 안 한 변경이 있는 레포는 이름이 노란색이고, 브랜치·↑↓·변경 수·작업 중은 줄에 마우스를 올리면 툴팁으로 보여요. "git 탭에서 보기"와 "레포 다시 읽기"는 줄을 오른쪽 클릭하면 나오고, 새 폴더를 만들었으면 탐색기 머리의 ↻를 눌러요. git 상태를 못 읽은 곳은 툴팁에 "모름"이라고 써요. 노드를 펼치면 파일 트리가 나와요.
- **열기·저장**: 탐색기에서 파일을 누르면 열려요. 고치면 탭에 ●가 붙고 Ctrl/Cmd+S로 저장해요. 닫을 때 저장하지 않은 게 있으면 물어요. 디스크에서 파일이 바뀌면 알려 주고, 덮어쓸지 디스크 내용을 불러올지 골라요.
- **앱 단축키**: Ctrl/Cmd+1~9, 0 으로 왼쪽 막대 위쪽 탭 열 개 전환, Ctrl/Cmd+, 로 Settings 열기, Ctrl/Cmd+Shift+/ 로 단축키 안내창. 창이 낮아 탭이 다 안 들어가면 위쪽 탭만 스크롤되고(스크롤바는 안 보이고 위/아래에 옅은 그늘이 생겨요) Settings·Report 단추는 늘 아래에 보여요. 지금 탭은 자동으로 보이는 곳까지 스크롤돼요.
- **작업 변경 되돌리기**: 끝난 작업 카드의 Changes 에서 파일을 펼치면 고쳐진 글 파일은 변경 덩어리(hunk)마다 **Revert hunk** 가 있어요. 누르면 확인 창을 거쳐 그 덩어리만 작업 전 모양으로 돌리고, 돌리기 전에 백업을 남겨서 **Undo the undo** 로 되살릴 수 있어요. 작업 뒤에 그 자리를 직접 고쳤으면 Conflict 로 건너뛰고 아무것도 바꾸지 않아요(다른 자리를 고친 것은 그대로 둬요). 새 파일·지운 파일·바이너리는 Revert file 로만 돼요. 임시 레포(줄 끝 LF·CRLF)로만 확인했고 맥은 확인하지 못했어요.
- **찾기**: 파일 안 찾기 Ctrl/Cmd+F, 작업 폴더 전체 찾기 Ctrl/Cmd+Shift+F, 파일 이름으로 빠른 열기 Ctrl/Cmd+P.
- **git 표시**: 탐색기에 M(수정)·A(추가)·U(새 파일)·D(삭제)·!(충돌), 편집기 왼쪽에 바뀐 줄(초록 추가, 파랑 수정, 빨강 삭제). 상태 줄의 "git에서 보기"로 git 탭에 이어가요.
- **안 열리는 것**: 작업 폴더 밖, 비밀 파일(.env·*.pem·*.key·id_rsa* 등과 .rauhaignore), 1MB 넘는 파일, 바이너리, UTF-8이 아닌 글. 작업 폴더를 바꾸면 열어 둔 파일이 모두 닫히고 저장 안 한 수정은 사라져요.
- **파일 아이콘**: 탐색기·파일 탭·빠른 열기·전체 찾기 결과에 파일 종류별 아이콘이 붙어요(VS Code의 Material 아이콘처럼 언어는 색 사각형+글자, 문서는 색 종이+그림, package.json·git·Dockerfile·설정은 자기 모양, 폴더는 src·test·docs·node_modules 같은 종류별 색과 그림). 직접 그린 그림이라 인터넷도, 따로 붙일 라이선스 표기도 필요 없어요.
- **미리보기**: .md 파일은 탭 줄 오른쪽의 [편집·나란히·미리보기]로 렌더된 모습을 볼 수 있어요(넓은 창에서는 처음에 나란히, 좁은 창에서는 나란히가 없어요. 고른 방식은 기억해요). HTML은 해석하지 않고 글자로 보이며, 링크는 http·https만 눌러져요(기본 브라우저로 열려요). 이미지는 작업 폴더 안의 그림 파일만 보이고 인터넷 주소·폴더 밖 그림은 [그림: 이름]으로만 나와요. png·jpg·gif·webp·svg·ico 파일을 탐색기에서 누르면 이미지 뷰어 탭으로 열려요(5MB까지, 누르면 원래 크기/창에 맞춤).
- **파일 조작(탐색기 안)**: 트리 위쪽 작은 도구줄(새 파일·새 폴더·이름 바꾸기·복제·옮기기·삭제)이나 항목을 오른쪽 클릭해서 해요. 줄을 고른 뒤 키보드로도 돼요: F2 이름 바꾸기, Delete 삭제, Ctrl/Cmd+C·V 복사·붙여넣기.
  - **이름 바꾸기·새로 만들기**: 그 자리에서 이름을 쳐요. 확장자를 뺀 이름만 먼저 골라져 있고, 쓸 수 없는 글자(`/  : * ? " < > |`)·`..`·Windows 예약 이름(CON·NUL 등)·`.git`·너무 긴 이름·같은 폴더의 같은 이름은 치는 즉시 이유가 아래에 나와요. Enter 확정, Esc 취소.
  - **삭제 = 휴지통**: 영구 삭제가 아니라 휴지통(Windows) / 휴지통(macOS)으로 가요. 확인 창에 폴더면 안의 파일 수가 보여요. 휴지통으로 못 보내면 지우지 않고 이유를 알려요(영구 삭제로 대신하지 않아요).
  - **복제·옮기기**: 복제는 "이름 복사본.확장자"로 만들고, 옮기기는 항목을 폴더로 끌어다 놓거나 "다른 폴더로 옮기기…"에서 골라요. 어느 쪽이든 같은 이름이 있으면 **덮어쓰지 않고 거절**해요. 폴더를 자기 안으로는 못 옮겨요. 경로 복사(절대/상대)와 "탐색기/Finder에서 보기"도 메뉴에 있어요.
  - **열려 있는 탭과 이어져요**: 이름을 바꾸거나 옮기면 탭이 새 이름으로 이어져요(수정 중인 글도 그대로). 지우면 탭이 닫혀요. 저장 안 한 수정이 있으면 확인 창에서 먼저 물어요("수정 중인 탭은 남기기"를 고르면 "지워졌어요"로 표시돼요).
  - **막아 둔 곳**: 작업 폴더 밖, 밖으로 가는 바로가기 너머, `.git`, `node_modules` 안, 쓰기 권한 없는 폴더는 조작하지 않아요. 작업 폴더 자체와 레포·문서 폴더 자체는 이름 바꾸기·옮기기·삭제를 막아요(안의 파일은 돼요). 비밀 파일(.env 등)은 이름 바꾸기·옮기기·삭제만 되고, 내용을 복제하지 않으며, 비밀이 아닌 이름으로 바꾸는 것도 막아요(내용이 열리게 되니까요).
  - **팀이 일하는 레포**: 팀이 지금 일하는 레포(진행 중 작업의 worktree 포함)의 파일을 바꾸려 하면 "충돌할 수 있어요" 경고를 레포마다 한 번 보여요. 사용자가 직접 하는 일이라 허락 카드는 없어요.
- **들여쓰기**: .editorconfig를 따르고, 없으면 파일에서 탭/스페이스를 알아내요.

### 터미널 칸 (진짜 터미널이에요)

탭 오른쪽 위 `>_ Terminal`(또는 Ctrl/Cmd+`)로 열어요. 탭 하나가 진짜 PTY(의사 터미널) 하나라서 vim·less·ssh·`npm run dev`·색·커서 이동·Ctrl+C·창 크기 변화가 VS Code 터미널처럼 돼요. 화면은 xterm.js가 그려요. (2026-11-11 구현. Windows 설치본에서만 확인했고 **맥은 확인하지 못했어요** — CI 맥 러너의 `smoke:features`가 처음 확인해요.)

- **여러 터미널**: 오른쪽 위 `+`(Ctrl/Cmd+Shift+`)로 새 터미널을 열어요. 작업 폴더나 그 아래 레포 중 하나를 골라 거기서 시작해요(최대 8개). 칸을 접어도(×, Ctrl/Cmd+`) 터미널은 계속 돌아요. 탭의 ×로 닫으면 돌던 프로그램과 그 자식까지 끝내요. `exit`로 셸이 끝나면 탭이 저절로 닫히고, 오류 코드로 끝나면 탭이 남아 그 코드를 보여 줘요.
- **셸은 앱이 정해요**: Windows는 PATH의 `pwsh`(PowerShell 7)가 있으면 그걸, 없으면 Windows PowerShell, 그것도 없으면 cmd. 맥·리눅스는 `$SHELL`(zsh·bash·fish 같은 알려진 셸)을 로그인 셸(`-l`)로 열고, 없으면 맥은 `/bin/zsh`. 화면이 실행 파일이나 인자를 정할 수는 없어요. 프로필(`.zshrc`, PowerShell 프로필)은 불러와요.
- **복사·붙여넣기·찾기**: 선택한 글은 Ctrl+Shift+C(맥 ⌘C)로 복사해요. Windows·리눅스에서는 선택이 있을 때만 Ctrl+C도 복사이고, 선택이 없으면 평소처럼 중단 신호(Ctrl+C)예요. 붙여넣기는 Ctrl+V / Ctrl+Shift+V(맥 ⌘V). Ctrl/Cmd+F(또는 ⌕ 단추)로 터미널 안 찾기 줄이 열려요(Enter 다음, Shift+Enter 이전, Esc 닫기).
- **링크**: Ctrl/Cmd+클릭으로 열어요. `https://` 주소는 기본 브라우저로(앱의 외부 링크 검사를 그대로 거쳐요), `경로:줄:칸`·`경로(줄,칸)` 모양의 파일 경로는 편집기로 열어 그 줄로 가요. 작업 폴더 밖 파일은 열지 않고 안내만 해요. 상대 경로는 그 터미널을 연 폴더 기준이에요(셸에서 `cd` 한 뒤의 위치는 앱이 알 수 없어요).
- **앱 단축키가 우선인 키**: 터미널에 포커스가 있어도 Ctrl/Cmd+숫자·쉼표·Shift+/·Shift+B, Ctrl/Cmd+`는 셸로 보내지 않고 앱이 받아요. 그 밖의 Ctrl 조합(Ctrl+D·Ctrl+R·Ctrl+Z 등)은 모두 셸로 가요.
- **안전**: 화면에서 오는 요청은 앱의 IPC 검사(믿는 화면에서 온 것만)를 거치고, 터미널 id는 앱이 만든 UUID만 받아요. 입력은 한 번에 64KB까지(긴 붙여넣기는 화면이 나눠 보내요). 셸이 받는 환경 변수에서 `RAUHA_*`·`ELECTRON_*`는 빼요(rauha 내부 값은 셸로 안 넘어가요). 화면이 못 따라갈 만큼 출력이 쏟아지면(`yes` 등) PTY 읽기를 잠깐 멈췄다가 화면이 그린 만큼만 다시 읽어서 메모리가 쌓이지 않아요. 터미널 스크롤 기록은 5000줄.
- **옛 줄 입력 방식과 달라진 것**: 예전 칸은 명령마다 새 셸을 띄우고 비밀 파일(.env 등)을 건드리는 명령(`cat .env`)을 막았어요. 진짜 터미널은 셸 안의 일을 앱이 들여다볼 수 없어서 **이 막기는 없어요.** 이 칸은 사람이 직접 치는 것이고 AI 팀원이 쓸 길은 없어요(출력도 채팅·기록에 들어가지 않아요). `rm -rf` 같은 명령도 그대로 실행되니 VS Code 터미널과 같은 수준으로 조심해 주세요.
- **앱 종료·작업 폴더 변경**: 앱을 끄거나 작업 폴더를 바꾸면 열린 터미널의 프로세스 트리를 모두 끝내요(Windows는 `taskkill /T`, 맥·리눅스는 프로세스 그룹에 SIGHUP, 1.5초 뒤 SIGKILL).
- **아직 없는 것**: 터미널 분할, 셸 선택 설정, 셸 통합(명령 표시·현재 폴더 추적), 글꼴 크기 설정, 화면 다시 열 때 이전 터미널 되살리기. 터미널 엔진(`@lydell/node-pty`)을 못 불러오면 칸에 이유가 한 줄로 떠요.

## 7-4. API 탭

왼쪽 막대의 API 탭(Todo 다음)은 Postman·Apidog 같은 요청 보내기 화면입니다. 메서드·주소·헤더·쿼리·본문(JSON·form·raw)·인증(Bearer·Basic·API key)으로 요청을 만들어 Send 하면 상태·시간·크기·헤더·본문(JSON 은 들여써서 색 표시)이 나오고, 느린 응답은 Cancel 로 바로 끊을 수 있어요(30초 넘으면 시간 초과, 본문은 5MB 까지만 읽어요). 요청은 Rauha 본체가 보내서 CORS 가 없고 http·https 만 됩니다. 왼쪽 목록에는 컬렉션·폴더와 기록이 있고, Manage 에서 환경(`{{base_url}}` 같은 변수)을 만들어요. 토큰 같은 비밀 변수는 `api-environments.json`(소유자만 읽기)에만 두고 컬렉션·기록·내보내기에는 `{{변수}}` 로만 남아요. Import 로 cURL·.http·OpenAPI 를 가져옵니다. 이 PC 의 로컬 서버로만 확인했고 맥은 확인하지 못했어요.

## 7-3. Docker 탭

왼쪽 막대의 Docker 탭은 `docker` 명령이 알려 주는 것을 보여 주고 다룹니다. 엔진(Docker Desktop·Colima·OrbStack·Podman)은 Rauha 밖이라 따로 설치해 켜 두어야 하고, 꺼져 있으면 이유와 설치 링크를 보여 줍니다. Containers·Images·Volumes·Networks·Compose 탭이 있고, 컨테이너는 시작·정지·재시작·삭제(확인 창)와 선택한 컨테이너의 최근 로그, 컨테이너 안 한 줄 명령(대화형 셸은 아님)을 지원합니다. 화면이 보일 때만 5초마다 새로 읽습니다. 지금은 가짜 docker 로만 확인했고 실제 엔진으로는 확인하지 못했습니다.

## 7-4. DB 탭

왼쪽 막대의 DB 탭(Docker 다음, Ctrl/Cmd+6)은 SQLite 파일을 열어 봅니다. 왼쪽에서 파일을 더하고(전체 경로를 적거나 Browse…), 테이블을 고르면 Schema(열·타입·기본 키·CREATE 문), Rows(100행씩, 열 머리를 눌러 정렬, 다음 쪽), SQL(편집기 + Run, Ctrl/Cmd+Enter) 탭에서 볼 수 있고, 결과와 행은 CSV로 내보낼 수 있습니다.

- **기본은 읽기 전용**입니다. INSERT·UPDATE·DELETE·CREATE·DROP·ALTER 는 오른쪽 위 Write mode 를 켜고, 실행 직전 확인 창에서 한 번 더 허락해야 돕니다(되돌릴 수 없음). ATTACH·VACUUM·트랜잭션·load_extension·값을 바꾸는 PRAGMA 는 Write mode 에서도 막습니다. 한 번에 한 문장만 돕니다.
- **상한**: 결과 5,000행 또는 5 MB, 칸 하나 4,000자, 쿼리 10초(10·30·60초 선택). 넘으면 잘렸다고 알려 주고, 시간이 지나면 SQLite 를 돌리던 프로세스를 통째로 멈춥니다. 쓰는 도중 멈췄으면 SQLite 저널로 되돌립니다. Cancel 로 직접 멈출 수도 있습니다.
- **엔진**: Electron 에 든 Node 의 내장 SQLite(`node:sqlite`)를 요청마다 따로 띄운 자식 프로세스에서 씁니다. 네이티브 모듈을 따로 싣지 않아 맥·윈도우 패키징에 영향이 없습니다. 자식에게는 API 키 같은 환경 변수를 넘기지 않습니다.
- **경로**: 화면은 연결 id 로만 파일을 고릅니다. 경로를 더할 때 main 이 절대 경로·`..` 없음·UNC/장치 경로 거절·실제 파일 여부·SQLite 머리 16바이트를 직접 확인합니다. 저장되는 것은 파일 경로 목록(`db-connections.json`)뿐이고 비밀은 없습니다.
- PostgreSQL/MySQL 은 아직 없습니다(설계 메모: `docs/design/db-tab.md`).

## 7-2. git 탭

맨 위 **동기화 툴바**가 GitHub Desktop처럼 늘 보여요. 모델을 부르지 않고 순수 git만 써요.

- **레포 · 브랜치**: 왼쪽에서 레포를 고르고, 큼직한 브랜치 이름을 누르면 팝업이 열려요. 검색 입력, 현재 브랜치가 맨 위, 로컬은 최근 커밋 순, 원격은 따로, 각 줄에 `↑앞섬 ↓뒤처짐`과 보호 브랜치 자물쇠가 보여요. 맨 아래 "새 브랜치 만들기…"로 대화상자를 열어요.
- **Fetch / Pull / Push**: 아이콘(Fetch ⟳, Pull ↓, Push ↑)과 글자가 늘 보이는 버튼이에요. 지금 가장 중요한 하나(커밋할 게 있으면 커밋, 아니면 뒤처졌으면 Pull, 앞섰으면 Push)만 파랗고, 나머지도 글자가 읽혀요.
  - Pull 버튼 옆 `↓3` = 받을 커밋 3개, Push 버튼 옆 `↑1` = 올릴 커밋 1개(굵은 글씨, 색과 함께 기호로도 구분돼요). Fetch 버튼 옆에는 마지막 확인 시각("5분 전", 한 번도 안 했으면 "아직 안 함")이 보여요.
  - 누르면 버튼에 스피너와 "가져오는 중…" 같은 진행 글이 보이고, 끝나면 툴바 아래에 한 줄 결과("새 커밋 3개를 받았어요", "이미 최신이에요", 실패하면 이유)가 잠깐 보여요. 실패 이유는 쉬운 말로 바꿔 줘요(예: push 거절 → "먼저 pull로 받아 합친 뒤 다시 push해 주세요").
  - 보호 브랜치(main·qa·release)에 push할 때는 전과 같이 확인 창이 떠요. 창이 좁아지면 글자는 숨고 아이콘과 `↑↓ 숫자`만 남아요(글자는 마우스를 올리면 툴팁으로 보여요).
- **새 브랜치 대화상자**: 이름을 치면 공백·금지 문자(`~ ^ : ? * [ \`, `..`, `@{`, 끝의 `.lock` …)와 이미 있는 이름을 바로 알려 주고, 이 레포가 쓰는 접두어(예: `feature/`)를 칩으로 제안해요(근거가 없으면 흔한 `feature/ fix/ chore/`). 기준 브랜치(기본 현재)를 고르고 "만들고 바로 이동"을 끌 수 있어요. 만들기 버튼이 막힌 이유는 버튼 옆에 한 줄로 보여요.
- **커밋 입력**: 제목(한 줄, 글자 수 `n/72`, 72를 넘으면 빨갛게 경고하지만 커밋은 할 수 있어요)과 설명(선택)을 나눴어요. 이 레포의 최근 커밋에서 읽은 방식("이 레포는 `feat(범위): 내용` 방식(한국어)이에요")과 말머리 칩, 제목 칸 예시가 보여요. 근거가 약하면 "아직 몰라요"라고 하고 칩은 없어요. 커밋 버튼 옆에 "3개 파일, +12 −4"가 보이고, 못 누를 때는 이유(스테이지한 파일 없음 · 제목 없음 · 충돌)가 아래에 한 줄로 나와요.
- **커밋 되돌리기**: 커밋 직후 "직전 커밋 취소"가 나와요. 확인 창을 거쳐 커밋만 없던 일로 하고 바뀐 내용은 스테이지에 남겨요(soft reset). 이미 원격에 올린 커밋과 첫 커밋은 취소하지 않아요.

### 커밋 그래프 · Blame · 3-way 충돌 (2026-11-11)

- **History 탭 그래프**: 커밋마다 왼쪽에 브랜치 선과 점이 이어져요. 병합 커밋은 속 빈 점 + "Merge" 칩, 줄기 색은 브랜치 이름으로 정해져요. "All branches"를 켜면 다른 브랜치의 커밋도 함께 보여요. 최근 500개까지만 그려요.
- **Blame**: Repo 탭 편집기 위 "Blame" 단추를 켜면 줄 왼쪽에 "작성자 · 날짜"가 떠요(같은 커밋이 이어지면 첫 줄에만). 저장한 파일 기준이고, 줄을 누르면 Git 탭 History 가 그 커밋을 골라서 열려요. 5000줄까지만, 아직 커밋 안 한 파일·레포 밖 파일은 이유만 알려 줘요.
- **3-way 충돌**: Conflicts 탭에서 구역마다 Mine · Base · Theirs 를 나란히 보고 "Accept mine / theirs / both / base"로 한 구역씩 풀어요. 다 풀리면 "Resolved". Base 는 git 이 충돌을 다시 합쳐 얻고(파일은 안 바뀜), 이미 손으로 고친 파일은 Base 없이 Mine/Theirs 만 보여요.

### 전체 검색 · 정의로 이동 · Problems (2026-11-11)

- **전체 검색**: Repo 탭 왼쪽 Search(Ctrl/Cmd+Shift+F). `Aa` 대소문자, `ab` 단어 단위, `.*` 정규식, `…` 로 포함/제외 칸(쉼표로 여러 개, `*.ts, src/**`)을 열어요. 결과는 파일별로 묶여 보이고 누르면 그 줄로 가요. node_modules·.git·dist 같은 생성물, 압축본(.min.js)·잠금 파일, 비밀 파일, 1MB 넘는 파일·바이너리는 건너뛰고(건너뛴 수가 요약에 나와요) 결과는 2000건·파일당 200건까지예요. 검색은 별도 스레드에서 돌아서 끝나지 않는 정규식은 몇 초 뒤 끊기고, Stop 으로 멈출 수 있어요.
- **정의로 이동**: 커서를 이름에 두고 F12 (또는 Ctrl/Cmd+클릭, 우클릭 메뉴). **참조 찾기**는 Shift+F12. TS/JS 파일은 앱에 들어 있는 typescript 가 프로젝트(가까운 tsconfig.json)를 읽어 답하고(처음엔 몇 초), 정의가 여럿이면 Search 칸에 목록으로 보여요. 다른 언어이거나 도구가 실패하면 그 이름을 단어 단위로 전체 검색해요. 쉬는 3분 뒤에는 도구를 끝내 메모리를 돌려줘요(실행 중에는 수백 MB 를 쓸 수 있어요).
- **Problems**: TS/JS 파일의 문법·타입 오류를 편집기 밑줄(빨강=오류, 노랑=경고)로 보이고, 아래 상태줄의 `Problems: …` 단추(Ctrl/Cmd+Shift+M)로 목록을 열어 누르면 그 자리로 가요. 열 때·저장할 때·고친 뒤 잠깐 쉴 때 갱신하고 30만 자 넘는 파일은 건너뛰어요.

## 8. 설정

왼쪽 맨 아래 톱니바퀴(맥은 Cmd+, 도 돼요). **계정**(Claude Code 설정 폴더 하나 = 계정 하나), **한도**(지금 세션 5시간·이번 주, %만 보여요. 70% 노랑, 90% 빨강. 아래 상태 줄에도 작게 있어요), 작업 폴더, 알림(허락·끝·한도 90%·단계), 채팅 배치(나란히/위아래), 보호 브랜치, 동시 실행 수.

### 팀 설정

설정 맨 아래 "팀 설정"에서 팀원 22명을 하나씩 바꿔요. **켜기·끄기**(팀장·접수, 라우터, 답변, 테스트, 구현, 리뷰어, 저장소 파악, 부서장은 작업 흐름에 꼭 필요해서 끌 수 없고, 나머지는 꺼요. 끈 팀원이 필요한 일을 맡기면 "꺼 둔 팀원이에요"라고 알려요), **모델 등급**(Haiku·Sonnet·Opus. 고르면 상태 머신의 승격 배정보다 앞서 그 등급으로 일해요), **노력 수준**, **도구**(읽기·찾기·웹·파일 고치기/만들기·명령 실행. 쓸 수 있는 파일 범위는 작업 범위와 역할 권한이 따로 지켜요), **추가 지시**(그 팀원 프롬프트 끝에 붙어요), **이름·캐릭터**(화면에 보이는 이름과 22종 중 그림, 이미 열린 말풍선은 다음에 열 때 바뀌어요). 팀원마다 "이 팀원 기본값으로", 맨 아래 "팀 전체 기본값으로"가 있어요.

- 기본값은 지금까지 동작 그대로예요. 아무것도 안 바꾸면 달라지는 게 없고, 바꾼 것만 저장돼요(기본과 같게 바꾸면 저장에서 사라져요).
- 바꾼 값은 앱 데이터(`~/.rauha/desktop/team.json`)에 저장되고 **다음 작업부터** 엔진에 반영돼요. 개발 실험용 `RAUHA_ROLE_<역할>` 환경 변수는 설정보다 앞서요.

### 모델 이름 (Models)

설정의 **Models** 구역에서 등급(Haiku·Sonnet·Opus)마다 실제로 부를 모델 ID를 바꿔요. 계정(특히 회사 계정)마다 쓸 수 있는 모델이 달라서, 기본 ID가 안 되는 계정에서도 쓸 수 있게 한 거예요.

- 기본값은 `claude-haiku-5-5` · `claude-sonnet-5-5` · `claude-opus-5-5`예요. 칸을 누르면 알려진 ID(`claude-fable-5-2`, `claude-fable-5-1`, `claude-fable-5`, `claude-opus-5`, `claude-sonnet-5` 등)가 제안으로 뜨고, 목록에 없는 ID도 직접 적을 수 있어요. 예를 들어 Opus 칸에 `claude-fable-5-2`를 적으면 Opus 등급 일을 그 모델로 해요(Fable 등급이 따로 생기는 건 아니에요).
- ID는 `claude-`로 시작하고 소문자·숫자·`.`·`_`·`-`만, 64자까지예요. 빈 값·공백이 있는 값·너무 긴 값은 저장하지 않고 이유를 보여 줘요(설정 파일이 이상해도 그 등급만 기본값으로 돌아가요). **Reset to default**를 누르면 세 칸이 모두 기본값으로 돌아가요.
- 바꾼 값은 **다음 요청부터** 적용돼요. 규칙 말로 적기와 블로그 초안(Haiku 등급)에도 같은 설정이 쓰여요.
- **모델 오류 시 대체 실행**: 모델이 없거나 이 계정에 권한이 없다는 오류로 팀원 호출이 실패하면, 같은 등급의 이전 버전 → 한 단계 낮은 등급(Opus → Sonnet → Haiku) 순으로 바꿔 다시 시도해요. 최대 2번이고 더는 돌지 않아요. 대체해서 성공하면 결과 글 끝에 "opus-5-5 모델을 쓸 수 없어서 대신 opus-5 모델로 실행했어요." 같은 한 줄이 붙어요. 이전 버전은 알려진 계보(Fable 5.2 → 5.1 → 5, Opus 5.5 → 5, Sonnet 5.5 → 5)만 쓰고, 계보에 없는 ID(Haiku 포함)는 이전 버전을 지어내지 않고 바로 낮은 등급으로 가요. 사용 한도·로그인 문제는 모델 오류가 아니라서 대체하지 않아요.

### 새 버전 알림

앱이 GitHub 릴리스를 보고 새 버전이 있으면 위쪽에 "새 버전 v0.1.2가 있어요 · [지금 업데이트] [브라우저로 받기] [나중에]" 띠를 보여 줘요. 시작 5초 뒤 한 번, 이후 6시간마다 확인해요. 자동으로 설치하지는 않고, **지금 업데이트**를 눌렀을 때만 시작해요.

**지금 업데이트**를 누르면 화면 가운데에 진행 창이 떠요. 확인 → 내려받는 중(퍼센트 막대, 받은 MB/전체 MB, 속도, 남은 시간) → SHA-256 확인 → 설치 준비 → "앱을 닫고 설치한 뒤 다시 켭니다" 순서예요.
- 닫을 수 있는 건 내려받는 중의 **취소**뿐이에요(취소하면 받은 파일을 지워요). 설치 단계에서는 닫을 수 없어요.
- 실패하면 창 안에 이유 한 줄과 **다시 시도 · 브라우저로 받기 · 진단 정보 복사 · 닫기**가 나와요. 30초 동안 데이터가 안 오면 멈춘 것으로 보고 실패로 알려요.
- 설정 > 새 버전의 **업데이트 확인**은 확인하는 동안 빙글빙글 표시가 돌고, 결과를 "최신 버전이에요 (v0.1.4)" / "새 버전 v0.1.5가 있어요" / "확인하지 못했어요: 이유"로 보여 줘요.
- 맥은 앱이 Downloads나 설치 파일(dmg) 안처럼 쓸 수 없는 임시 위치에서 열려 있으면 `/Applications/Rauha.app`(권한이 없으면 `~/Applications/Rauha.app`)에 설치하고, 진행 창에 어디에 설치하는지 알려 줘요.
- 설치는 앱이 꺼진 뒤 따로 도는 프로그램이 하니, 결과는 다시 켜졌을 때 알려요. 새 버전이 켜지면 "v0.1.5로 업데이트됐어요", 버전이 그대로면 "업데이트가 적용되지 않았어요: 이유"가 위쪽 띠에 떠요. 자세한 기록은 앱 데이터 폴더의 `logs/update-swap.log`에 남아요.

- 브라우저로 받은 맥 설치 파일은 처음 열 때 경고가 뜰 수 있어요. 터미널에서 `xattr -dr com.apple.quarantine /Applications/Rauha.app` 한 줄을 실행해요(띠 아래에도 안내가 나와요). 앱 안 **지금 업데이트**로 받은 파일에는 이 경고가 뜨지 않아요.
- "나중에"를 누른 버전은 더 높은 버전이 나올 때까지 띠를 숨겨요.
- 설정 > 새 버전에서 현재 버전, "업데이트 확인" 버튼, 마지막 확인 시각, "자동으로 확인" 켜기/끄기(기본 켬)를 볼 수 있어요. 끄면 자동 확인만 멈추고 버튼은 그대로 써요.

### 답답한 점 적기 + 내 AWS에 올리기

쓰다가 답답한 점은 **어느 탭에서나 Ctrl+Shift+B(맥은 Cmd+Shift+B)** 나 왼쪽 막대 맨 아래 **답답함** 단추로 적어요. 제목 한 줄(꼭, 80자까지)과 메모(선택)를 쓰면 화면 이름·앱 버전·OS가 자동으로 붙고, **이 컴퓨터에 먼저 저장돼요**(인터넷이 없어도 잃지 않아요). 목록은 미해결/해결로 나뉘고, 메모마다 **수정 요청으로 쓰기**(채팅 입력칸에 채워 줘요, 보내지는 않아요)·**할 일 카드로**·**해결**·지우기(확인 창)가 있어요. 모델은 부르지 않아요.

집에서 이어서 고치려면 내 개인 AWS(S3)에 올려 두고 받아요.
1. 맥북·집 PC 터미널에서 한 번: `aws configure --profile rauha-personal`(키는 터미널에만 적어요. 앱은 키를 받지도 저장하지도 읽지도 않아요).
2. Rauha 설정 > **내 AWS**에 **프로필 이름**(위에서 정한 이름)·**버킷**·**리전**·**개인 계정 번호(12자리)** 를 적어요.
3. 답답한 점 창의 **내 AWS로 올리기** → **가려진 미리보기**를 확인하고 **확인하고 올리기**. 집에서는 같은 설정으로 **받아오기**를 눌러요.

- 프로필 이름을 직접 적기 전에는 올리기·받아오기가 꺼져 있어요(default 프로필을 대신 쓰지 않아요).
- 올리거나 받기 직전에 그 프로필의 실제 계정 번호를 확인해서, 적어 둔 개인 계정과 다르면 멈추고 이유를 보여 줘요(회사 계정에 올리는 사고 방지).
- 올리기 전에 회사·서비스 이름(설정의 블로그 가림 이름)·레포 이름·도메인·IP·키·이메일을 가려요. 이 컴퓨터의 메모는 그대로예요.
- 저장 위치는 `bug-notes/<번호>.json`(버전 관리를 켠 버킷이면 덮어써도 돼요). 올리기가 실패해도 이 컴퓨터 메모는 그대로이고, 받아올 때 같은 번호는 해결 표시가 더 늦은 쪽을 따라요.

## 9. 문제가 생기면

- **앱이 안 떠요**: 맥은 위 설치 3~4단계를 다시 해요. 그래도 안 되면 소스로 실행해요(아래).
- **로그인 만료**: 3번처럼 다시 로그인해요.
- **한도 90%**: 새 일을 아껴요. 위쪽 한도 막대의 "초기화" 시각 뒤에 풀려요. 큰 일은 미루는 게 좋아요.
- **일이 멈췄어요**: 일 카드와 채팅에 이유가 나와요. 팀이 테스트를 못 만들거나 리뷰가 반복돼 멈추는 경우가 있어요(문서만 고치는 일도 코드 일로 보고 멈춘 적이 있어요). 요청을 질문이나 문서 요청으로 바꿔 다시 맡겨 봐요.
- **원인을 알려야 할 때**: 설정 맨 아래 "도움말"의 **진단 정보 복사** 버튼(또는 입력창에 `/진단`)을 누르고 복사된 글을 개발자에게 붙여 넣어요. 앱 버전, 컴퓨터, 로그인·도구 상태, 최근 오류 로그가 한 덩어리로 들어가고 이메일·홈 경로·키는 가려져요.
- **글자를 칠 때 느려요**: 개발 PC에서는 재현되지 않았어요. 느낀다면 어떤 때인지 알려 주세요.

## 10. 소스로 실행하기 (설치가 안 될 때)

Node 22 이상, git, yarn(Yarn 4)이 필요해요.

```
git clone https://github.com/kimvudghk11/rauha.git
cd rauha
yarn install
yarn build
yarn desktop
```

`yarn desktop`이 앱 창을 띄워요. 작업 폴더는 첫 실행 안내에서 골라요.
