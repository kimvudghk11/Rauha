# rauha 데스크톱 사용 안내 (한 장)

처음 쓰는 사람을 위한 안내예요. 확인하지 못한 것은 "확인 못 함"이라고 적었어요.

## 1. 설치

설치 파일은 GitHub Releases에서 로그인 없이 받아요: https://github.com/kimvudghk11/rauha/releases (README의 "바로 내려받기" 링크도 같아요). 파일 배치와 빌드 방법은 `packages/desktop/PACKAGING.md`에 있어요.

**맥북(macOS)**
1. `rauha-…-mac-arm64.dmg`(Apple 칩, M1 이상)나 `rauha-…-mac-x64.dmg`(인텔) 중 내 맥에 맞는 것을 받아 열어요(Apple 메뉴 → 이 Mac에 관하여에서 칩을 볼 수 있어요).
2. 열리는 창에서 rauha 아이콘을 Applications 폴더로 끌어다 놓아요.
3. 처음 열면 **"Apple은 rauha에 … 악성 코드가 없음을 확인할 수 없습니다"** 경고가 떠요. 서명이 없는 앱이라 나오는 정상 경고예요(고장이 아니에요). 아래 둘 중 하나로 열어요.
   - **터미널 한 줄(가장 빠름)**: `xattr -dr com.apple.quarantine /Applications/Rauha.app` 을 실행하고 앱을 다시 열어요.
   - **시스템 설정**: 앱을 한 번 열어 경고에서 **완료**를 눌러요. 그다음 시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 "rauha가 차단되었습니다" 옆 **그래도 열기** → 암호나 Touch ID → **열기**. macOS 15(Sequoia)부터는 예전의 "우클릭 → 열기"가 통하지 않아요.
4. 회사 보안 소프트웨어가 막으면 아래 "소스로 실행하기"로 가요.

**Windows**
`rauha-Setup-…-x64.exe`를 받아 실행해요. 서명이 없어서 "알 수 없는 게시자" 경고가 뜨면 "추가 정보 → 실행"을 눌러요.

## 2. 처음 열면

- **권한 허용**: 알림 권한을 물으면 허용해요(허락이 필요할 때 알려 줘요). 맥은 문서·데스크톱 폴더에 처음 접근할 때 묻는 창이 뜨면 허용해요. 알림이 안 보이면 시스템 설정 → 알림에서 rauha를 켜요.
- **첫 실행 안내(3단계)**: ① 일할 **작업 폴더**를 골라요(레포와 문서 폴더가 들어 있는 폴더 하나) → ② 그 폴더에서 일해도 되는지 **허락** → ③ 쓸 **Claude 계정** 고르기(모르면 "폴더 규칙에 맡기기"). 폴더를 고르고 허락하기 전에는 일을 맡길 수 없어요.
- **예전 터미널 rauha**가 PC에 있으면 "지울까요?" 창이 떠요. 어떤 파일을 지우는지 보여 주고, "지우기"를 눌러야만 지워요. 기억·학습 노트·대화 기록은 그대로예요. 모르겠으면 "그대로 두기".

## 3. Claude 로그인 (안 돼 있을 때)

rauha는 Claude 구독 로그인을 그대로 써요. 토큰은 읽지도 옮기지도 않아요. 일을 맡겼는데 "로그인되어 있지 않거나 만료됐어요"라고 나오면 터미널에서 Claude Code로 로그인해요: `claude auth login` (계정을 나눠 쓰면 그 계정의 설정 폴더로). 로그인한 뒤 앱에서 다시 맡겨요.

## 4. 일 맡기기

- 아래 입력창에 쓰고 **Enter**(줄바꿈은 Shift+Enter). 보낸 뒤에도 바로 다음 일을 보낼 수 있어요. 동시에 3개까지 돌고(설정에서 바꿔요, 다음 실행부터 적용) 넘치면 "대기"예요.
- **`@폴더이름`**을 맨 앞에 쓰면 그 레포·폴더에서 일해요. 예: `@api-server 결제 타임아웃 원인 찾아줘`. 이름은 레포 탭에서 볼 수 있어요.
- **`/명령`**(명령어 탭): 입력창에 `/`를 치면 명령 목록이 자동완성으로 떠요(↑↓ 고르기, Tab으로 채우기, Enter로 보내기, Esc 닫기). 터미널판 rauha의 슬래시 명령이 **기본 명령**으로 처음부터 들어 있어요. 명령어 탭에서 이름·설명·하는 일·인자를 볼 수 있고, 기본 명령은 끄거나("기본 명령 되돌리기"로 한꺼번에 켜요), **내 명령**(이름 + 프롬프트 템플릿 + 인자 `{{x}}`)을 더하고 고치고 지울 수 있어요. 인자는 `{{요청}}`(꼭 채움), `{{브랜치|main}}`(안 채우면 main)처럼 적고, 마지막 인자는 남은 글 전부를 받아요. 명령이 아닌 글을 `/`로 시작해 보내려면 `//`로 시작해요.
  - 팀에 일을 맡기는 명령: `/review [브랜치]`(변경 리뷰, 파일은 안 고침), `/design <요청>`(설계부터), `/learn [범위]`(패턴 복습), `/company`(부서별 정한 것 요약), `/개선 <대상> <요청>`(= `/improve`).
  - 앱이 바로 하는 명령(모델을 안 불러요): `/repo`(레포 탭), `/routine`(할 일 탭), `/team`(설정의 팀 설정), `/clear`(채팅 화면 비우기, 돌고 있는 작업은 그대로), `/status`, `/queue`, `/usage`(%만), `/guide`(지난 작업 정리 열기), `/copy`(마지막 답 복사), `/진단`(진단 정보 복사), `/retry`(마지막 요청 다시), `/help`, `/exit`(창 닫기).
  - `/설치`(= `/install`): 이 컴퓨터에 맞는 설치 방법. 맥은 `curl -fsSL https://raw.githubusercontent.com/kimvudghk11/rauha/main/scripts/install-mac.sh | bash` 한 줄을 **복사 버튼**으로 줘요(브라우저로 받지 않아서 첫 실행 경고가 안 떠요). Windows는 최신 설치 파일 내려받기 버튼이에요.
  - `/업데이트`(= `/update`): 새 버전이 있는지 확인하고 같은 방법을 보여줘요.
  - `/개선 <대상> <요청>`: 업데이트 요청이 올 때 쓰는 3단계예요. ① 공격적 점검(약점 분석·부족한 기능·보안·모의 해킹 관점의 취약점 탐색, 읽기 중심, 파괴 동작은 안 해요, 내 소유 프로젝트만) ② 그 결과를 근거로 개선 ③ 추가 테스트와 마무리. 한 작업으로 올라가 팀 방에서 진행이 보이고, 각 단계 결과가 다음 단계 입력이 돼요. 허락 카드와 규칙(비밀 파일·push 금지)은 그대로예요.
  - 터미널판의 `!명령`(모델 없이 바로 실행)은 앱에는 옮기지 않았어요.
- 질문에는 보통 빨리 가볍게 답하고, 답 아래 **"더 깊게"** 를 누르면 같은 질문을 깊게 다시 답해요. 저장소 정보를 아직 못 읽은 채 답했으면 그 답 카드 안에 "저장소 정보를 아직 못 읽었어요"라고 나와요.
- 일 카드의 **멈추기**로 언제든 멈출 수 있어요.

## 5. 팀 방과 허락 카드

- 일이 시작되면 오른쪽에 **팀 방**이 생겨요. 캐릭터(팀원), 진행 단계 막대, 마지막 한 줄, 걸린 시간이 보이고, 끝나면 잠시 뒤 사라져요. 방을 누르면 **팀 상세**가 열려요(기본은 "정리", "원본 로그" 탭에서 원본을 봐요).
- 팀이 위험한 일을 하려면 **허락 카드**가 떠요(오른쪽 아래 알림과 Windows·맥 알림). 읽는 법:
  - 맨 위 한 줄: 무슨 일인지(예: "main 브랜치에 push")와 요청한 팀원.
  - **코드**: 보호 브랜치(main·qa·release …)에 주는 영향 표 — 앞선/뒤처진 커밋 수, 충돌 여부, 자동 배포 여부 — 와 바뀐 파일, "diff 보기".
  - **인프라**: 환경(운영 여부), 계정·리전, 영향 범위, 중단 여부, 비용 방향(늘어남·줄어듦·같음만, 금액은 안 보여요), 되돌리는 시간, qa에 먼저 적용했는지. 알 수 없는 칸은 **"모름"** 이에요(지어내지 않아요). "원본 명령"도 펼쳐 볼 수 있어요.
  - 버튼: **한 번만 허락** / **이번 작업 동안 허락** / **다르게 해 줘**(말로 고쳐서 보내요) / **거절**.
- 비밀 파일(`.env` 등) 읽기·쓰기와 `git push`는 허락 카드와 상관없이 막혀 있어요(규칙으로도 풀 수 없어요).
- 같은 레포에 일이 둘 이상 돌면 두 번째부터는 따로 복사한 작업 폴더(worktree)에서 일하고, 끝나면 고친 내용을 `rauha/job-…` 브랜치로 남겨요. 합치는 것은 허락 카드를 거쳐요.

## 6. 규칙 탭

내 규칙을 칸 셋으로 나눠 적어요: **항상 지킬 것**(팀원에게 늘 알려 줘요) / **묻지 않고 할 것** / **꼭 허락받을 것**. 범위는 전체·작업 폴더·특정 폴더예요.

- **말로 적기**: 한 문장으로 적고 "정리하기"를 누르면 가장 가벼운 모델을 한 번 불러 칸·범위·찾을 글을 정리해 아래 칸에 채워 줘요. 확인하고 고친 뒤 "규칙 더하기"를 눌러야 들어가요(모델 호출 1번).
- **기본 규칙**: 규칙 탭에는 rauha를 만들며 정한 규칙이 "기본" 표시로 처음부터 들어 있어요. 항상 지킬 것(비밀 파일 읽기·쓰기 금지, 화면에 달러 금액 쓰지 않기, 확인 못 한 값은 "모름"으로 쓰기, aws 점검은 aws configure 프로필로 바로 실행), 묻지 않고 할 것(기본 git 읽기·준비, aws 조회, 테스트·타입 검사·빌드, 브라우저·claude 연동 확인), 꼭 허락받을 것(main·qa·release 보호 브랜치 push·merge, 운영 인프라 변경·삭제·비용이 느는 일). 카드마다 **켬/끔**, **고치기**(글과 찾을 글), **기본값으로**가 있고 아래 "기본 규칙 모두 되돌리기"로 한꺼번에 처음 상태로 돌려요.
  - 기본 규칙을 꺼도 비밀 파일 차단과 팀원의 `git push` 거절은 규칙보다 먼저 늘 지켜져요(카드에 작게 적혀 있어요). "묻지 않고 할 것" 기본 규칙은 앱이 이미 허용하는 명령만 담아서, 앱이 묻는 명령(예: git reset)을 풀어 주지 않아요.
  - 여러 명령을 이은 글(`a && b`)은 "묻지 않고 할 것" 규칙으로 통째로 풀리지 않아요. 맞는 한 조각 때문에 위험한 다른 조각이 묻지 않고 지나가면 안 되니까요.
- "묻지 않고/꼭 허락받을 것"은 **찾을 글**(명령이나 경로에 들어 있는 글, 예: `terraform apply`)로 판정해요. 둘 다 맞으면 "꼭 허락받을 것"이 먼저예요.

## 6-1. 할 일 탭과 기록 탭

- **할 일 탭**: 할 일 · 진행 · 완료 세 칸이에요. "＋ 새 할 일"로 제목·메모·우선순위·마감일·레포·맡길 팀을 적어요. 카드에서 완료 체크, 시작, 고치기, 지우기(한 번 더 눌러야 지워져요)를 하고, 위쪽에서 검색·상태·우선순위·레포·팀으로 거르고 우선순위순·마감순·최신순으로 정렬해요. 마감이 지난 카드는 빨갛게 보여요.
  - **팀에 맡기기**: 카드의 버튼을 누르면 `@레포 제목`과 메모가 메인으로 가고 카드는 진행 칸으로 가요. 작업이 끝나면 완료로, 멈추면 다시 할 일로 돌아와요. 앱을 껐다 켜면 살아 있지 않은 작업에 매인 진행 카드는 할 일로 돌아와요.
  - **채팅에서 담기**: 메인에서 보낸 일 카드의 "할 일로 담기"를 누르면 그 일이 할 일로 저장돼요.
  - 저장은 이 PC의 `~/.rauha/desktop/todos.json`이에요. 파일이 깨지면 `.broken-시각` 복사본을 남기고 열어요.
- **기록 탭**: 끝난 작업(끝남·멈춤)마다 요약이 자동으로 쌓여요: 요청, 일한 팀원, 거친 단계, 시작·끝 시각과 걸린 시간, 결과 요약, 바뀐 파일, 허락 결정과 이유. 방향을 고를 일에서 AI 추천과 다르게 골랐거나 허락 때 "다르게 해 줘"라고 했으면 "내가 다르게 골랐어요"가 붙어요.
  - 태그(트러블슈팅·네트워크 구성·인프라·설계·기능 구현·보안·성능·문서·기타)는 요청 글로 어림해 붙이고, 눌러서 바꿀 수 있어요. 검색과 태그·상태·레포·기간·"다르게 골랐어요" 필터가 있어요.
  - "마크다운으로 복사"는 문제 → 접근 → 방향 → 결과 순서로 포트폴리오·이력서에 옮겨 쓰기 좋게 뽑아요. 메모칸에 면접에서 말할 것을 적어 둘 수 있어요.
  - **요약만 남아요**: 토큰·키·비밀번호 모양의 값, 코드 블록, 전체 로그, 달러 금액, `.env`·키 파일 이름은 기록에 넣지 않아요(결과는 12줄·600자까지). 앱이 꺼진 사이에 끝난 작업은 기록되지 않아요.
  - 저장은 `~/.rauha/desktop/records.json`이에요(2000개가 넘으면 오래된 것은 지우지 않고 `records.json.archive.jsonl`로 옮겨요). AWS(S3) 전송은 아직 없어요.

## 7. 레포 탭

작업 폴더 안의 레포·문서 폴더 목록이에요: 브랜치, 원격과의 차이(↑앞섬 ↓뒤처짐), 바뀐 파일 수, 지금 일하는 작업 수("worktree 작업 중"도 표시). 새 폴더를 만들었으면 "다시 읽기"를 눌러요.

## 7-1. 코드 탭

VS Code를 열지 않고 파일을 보고 고치는 곳이에요. 왼쪽 탐색기, 위쪽 파일 탭, 아래 터미널 칸으로 되어 있어요.

- **열기·저장**: 탐색기에서 파일을 누르면 열려요. 고치면 탭에 ●가 붙고 Ctrl/Cmd+S로 저장해요. 닫을 때 저장하지 않은 게 있으면 물어요. 디스크에서 파일이 바뀌면 알려 주고, 덮어쓸지 디스크 내용을 불러올지 골라요.
- **찾기**: 파일 안 찾기 Ctrl/Cmd+F, 작업 폴더 전체 찾기 Ctrl/Cmd+Shift+F, 파일 이름으로 빠른 열기 Ctrl/Cmd+P.
- **git 표시**: 탐색기에 M(수정)·A(추가)·U(새 파일)·D(삭제)·!(충돌), 편집기 왼쪽에 바뀐 줄(초록 추가, 파랑 수정, 빨강 삭제). 상태 줄의 "git에서 보기"로 git 탭에 이어가요.
- **안 열리는 것**: 작업 폴더 밖, 비밀 파일(.env·*.pem·*.key·id_rsa* 등과 .rauhaignore), 1MB 넘는 파일, 바이너리, UTF-8이 아닌 글. 작업 폴더를 바꾸면 열어 둔 파일이 모두 닫히고 저장 안 한 수정은 사라져요.
- **들여쓰기**: .editorconfig를 따르고, 없으면 파일에서 탭/스페이스를 알아내요.

### 터미널 칸 (한계가 있어요)

탭 오른쪽 위 `>_`(또는 Ctrl/Cmd+`)로 열어요. 입력줄 하나와 출력 창이고, 터미널을 여러 개 열 수 있어요(작업 폴더나 그 아래 레포에서 시작).

- **진짜 터미널(PTY)이 아니에요.** 네이티브 모듈은 맥·Windows 설치 파일을 깨뜨릴 위험이 커서 쓰지 않아요. 그래서 vim·top·less·ssh 비밀번호·파이썬 대화 모드 같은 대화형 프로그램은 안 돼요. 화면에도 한 줄로 적혀 있어요.
- 명령 하나마다 새 셸을 띄워요(맥·리눅스는 `$SHELL -c`, 앱이 시작할 때 읽어 둔 로그인 셸 PATH를 써요. Windows는 PowerShell `-NoProfile`). 그래서 `cd`만 터미널이 기억하고, `export`나 `$env:` 같은 환경 변수 변경, alias·셸 함수, 프로필 설정은 다음 명령으로 이어지지 않아요. `cd a && npm test`처럼 한 줄에 이으면 돼요.
- 돌고 있는 명령이 있을 때 입력줄에 치면 그 명령의 입력으로 들어가요. Ctrl+C나 "멈추기"로 끝내요(자식 프로세스까지). 출력은 한 명령에 4MB를 넘으면 멈추고, 화면에는 최근 2000줄만 남겨요.
- **안전 규칙**: 이 입력은 사람이 직접 치는 것이라 AI 팀원의 허락 흐름(ToolRisk)을 거치지 않아요. `rm -rf` 같은 위험한 명령도 그대로 실행돼요. 다만 비밀 파일(.env 등)을 건드리는 명령(`cat .env`, `type .env*`, 비밀 파일이 있는 레포에서 `grep -r`)은 편집기와 같은 규칙으로 막아요. 이 막기는 실수를 줄이는 장치이지 보안 경계가 아니에요(셸은 얼마든지 돌려 쓸 수 있어요). AI 팀원이 이 칸에 입력할 길은 없고, 출력은 채팅·기록에 들어가지 않아요. `cd`는 작업 폴더 밖으로도 갈 수 있어요.
- 앱을 끄거나 터미널을 닫으면 돌고 있던 명령을 끝내요.

## 8. 설정

왼쪽 맨 아래 톱니바퀴(맥은 Cmd+, 도 돼요). **계정**(Claude Code 설정 폴더 하나 = 계정 하나), **한도**(지금 세션 5시간·이번 주, %만 보여요. 70% 노랑, 90% 빨강. 아래 상태 줄에도 작게 있어요), 작업 폴더, 알림(허락·끝·한도 90%·단계), 채팅 배치(나란히/위아래), 보호 브랜치, 동시 실행 수.

### 팀 설정

설정 맨 아래 "팀 설정"에서 팀원 22명을 하나씩 바꿔요. **켜기·끄기**(팀장·접수, 라우터, 답변, 테스트, 구현, 리뷰어, 저장소 파악, 부서장은 작업 흐름에 꼭 필요해서 끌 수 없고, 나머지는 꺼요. 끈 팀원이 필요한 일을 맡기면 "꺼 둔 팀원이에요"라고 알려요), **모델 등급**(Haiku·Sonnet·Opus. 고르면 상태 머신의 승격 배정보다 앞서 그 등급으로 일해요), **노력 수준**, **도구**(읽기·찾기·웹·파일 고치기/만들기·명령 실행. 쓸 수 있는 파일 범위는 작업 범위와 역할 권한이 따로 지켜요), **추가 지시**(그 팀원 프롬프트 끝에 붙어요), **이름·캐릭터**(화면에 보이는 이름과 22종 중 그림, 이미 열린 말풍선은 다음에 열 때 바뀌어요). 팀원마다 "이 팀원 기본값으로", 맨 아래 "팀 전체 기본값으로"가 있어요.

- 기본값은 지금까지 동작 그대로예요. 아무것도 안 바꾸면 달라지는 게 없고, 바꾼 것만 저장돼요(기본과 같게 바꾸면 저장에서 사라져요).
- 바꾼 값은 앱 데이터(`~/.rauha/desktop/team.json`)에 저장되고 **다음 작업부터** 엔진에 반영돼요. 개발 실험용 `RAUHA_ROLE_<역할>` 환경 변수는 설정보다 앞서요.

### 새 버전 알림

앱이 GitHub 릴리스를 보고 새 버전이 있으면 위쪽에 "새 버전 v0.1.2가 있어요 · [내려받기] [나중에]" 띠를 보여 줘요. 시작 5초 뒤 한 번, 이후 6시간마다 확인하고, 오프라인이거나 실패하면 조용히 넘어가요. **자동으로 설치하지는 않아요.** 내려받기를 누르면 내 컴퓨터(맥 Apple 칩·인텔, Windows)에 맞는 설치 파일이 브라우저로 열리고, 받은 파일로 다시 설치해요.

- 맥: 받은 뒤 Applications에 덮어쓰고, 처음 열 때 경고가 뜨면 터미널에서 `xattr -dr com.apple.quarantine /Applications/Rauha.app` 한 줄을 실행해요(띠 아래에도 안내가 나와요).
- "나중에"를 누른 버전은 더 높은 버전이 나올 때까지 띠를 숨겨요.
- 설정 > 새 버전에서 현재 버전, "업데이트 확인" 버튼, 마지막 확인 시각, "자동으로 확인" 켜기/끄기(기본 켬)를 볼 수 있어요. 끄면 자동 확인만 멈추고 버튼은 그대로 써요.

## 9. 문제가 생기면

- **앱이 안 떠요**: 맥은 위 설치 3~4단계를 다시 해요. 그래도 안 되면 소스로 실행해요(아래).
- **로그인 만료**: 3번처럼 다시 로그인해요.
- **한도 90%**: 새 일을 아껴요. 위쪽 한도 막대의 "초기화" 시각 뒤에 풀려요. 큰 일은 미루는 게 좋아요.
- **일이 멈췄어요**: 일 카드와 채팅에 이유가 나와요. 팀이 테스트를 못 만들거나 리뷰가 반복돼 멈추는 경우가 있어요(문서만 고치는 일도 코드 일로 보고 멈춘 적이 있어요). 요청을 질문이나 문서 요청으로 바꿔 다시 맡겨 봐요.
- **원인을 알려야 할 때**: 설정 맨 아래 "도움말"의 **진단 정보 복사** 버튼(또는 입력창에 `/진단`)을 누르고 복사된 글을 개발자에게 붙여 넣어요. 앱 버전, 컴퓨터, 로그인·도구 상태, 최근 오류 로그가 한 덩어리로 들어가고 이메일·홈 경로·키는 가려져요.
- **글자를 칠 때 느려요**: 개발 PC에서는 재현되지 않았어요. 느낀다면 어떤 때인지 알려 주세요.

## 10. 소스로 실행하기 (설치가 안 될 때)

Node 22 이상, git, yarn(Yarn 4)이 필요해요.

```
git clone https://github.com/kimvudghk11/rauha.git
cd rauha
yarn install
yarn build
yarn desktop
```

`yarn desktop`이 앱 창을 띄워요. 작업 폴더는 첫 실행 안내에서 골라요.
