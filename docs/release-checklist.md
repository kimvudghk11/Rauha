- **허락 카드**: 코드(바뀐 파일·diff·main/qa 영향표: 앞섬·뒤처짐·시험 머지 충돌·CI로 짐작한 자동 배포), 인프라(위험도 표, 모르는 칸은 "모름"), 버튼 4개, 앱 안 알림과 시스템 알림.
- **규칙 탭**: 칸 셋·범위·찾을 글, 도구 호출 판정(비밀 파일·역할 권한·git push 거절은 규칙보다 먼저), "항상 지킬 것"을 팀원 프롬프트에 넣기, 말로 적기(haiku 한 번).
- **레포 탭**(작업 폴더 훑기, 상태, worktree 표시), **설정**(계정·한도 %·알림·배치·권한), **첫 실행 마법사**(폴더·허락·계정), 터미널 rauha 찾아서 확인 후 지우기.

## 알려진 문제

- **입력 지연**: 개발 PC에서 재현되지 않았어요(키 입력→화면 p50 약 5~10ms). 실제 한글 키보드에서의 지연은 확인 못 함. 측정 스위치 `RAUHA_MEASURE_TYPING`만 남겨 뒀어요.
- **worktree**는 원래 폴더의 커밋 안 한 변경과 `node_modules`를 보지 못해요(지금 HEAD를 새로 checkout해요). 실제 Claude 팀으로 worktree 흐름을 돌려 본 적은 없어요(단위·git 통합 테스트로만 확인).
- **운영 팀원의 `rauha-risk` 줄**(인프라 위험도 칸을 채우는 한 줄)을 운영 팀원이 실제로 적는지는 확인 못 함. 안 적으면 해당 칸은 "모름"이에요.
- **문서만 고치는 요청(고쳤어요, 44ea670)**: 예전엔 "README에 한 줄 추가"가 코드 작업(테스트 먼저)으로 분류돼 멈췄어요. 이제 문서 파일만 가리키는 요청은 문서 경로로 가요. 실제 호출로 확인: 호출 2번, 13.4초, README만 바뀜(고치기 전: 호출 9번, 93초, 멈춤).
- **테스트가 있는 저장소의 코드 수정(실제 호출로 확인, 21a9803)**: 임시 Node 프로젝트(`node --test`)에서 "average 함수 추가" 요청이 호출 6번(haiku 4·sonnet 2), 53.7초에 끝났고 테스트 6개가 통과했어요. 커밋은 만들지 않고 변경만 남겨요.
- **테스트 환경이 없는 저장소에서 코드 수정 요청**은 테스트 팀원이 막혀 멈춰요(스킵·안내 없음, 코드로만 확인). 월요일 이후 설계 항목이에요.
- 위 실제 호출 확인은 **Windows 개발 PC**에서 core를 직접 부른 것이에요. 설치본·맥에서의 실제 일 맡기기는 확인 못 함.
- 규칙의 "찾을 글" 판정은 단순 포함 검사예요. 규칙이 의도보다 넓거나 좁을 수 있어요.
- 인프라 위험도의 영향 범위·되돌리는 시간 같은 칸은 모델이 쓴 글이라 틀릴 수 있어요(비용은 방향만).
- 작업이 끝난 뒤에도 같은 질문 카드의 "더 깊게"는 한 번 누르면 새 작업이 하나 더 생겨요(이전 대화 맥락은 이어지지 않아요).
- 작업 폴더를 고르기 전에는 일을 받지 않아요(개발용 환경 변수 `RAUHA_WORK_DIR` 제외).

## 맥에서 확인 못 한 것

이 PC에는 맥이 없어서 **실제 맥북에서 실행해 보지 못했어요.** 맥은 GitHub Actions(macos-latest) 결과만 근거예요.

- 설치 파일(dmg·zip)이 실제로 열리고 실행되는지, ad-hoc 서명 앱이 Gatekeeper를 "우클릭 → 열기"로 통과하는지: 확인 못 함.
- 로그인 셸에서 PATH를 읽어 `git`·`aws`·`gh`·`node`·`claude`를 찾는지(Finder로 연 앱): 확인 못 함(순수 함수 부분만 테스트).
- Claude Code 실행 파일(`claude`)이 설치본의 asar 밖에서 실행되는지, 맥 칩(arm64·x64)별로 맞는 것이 들어갔는지: 확인 못 함.
- 맥 창 모양(제목 막대 숨김·신호등 위치), Cmd 단축키, Dock 아이콘, 알림 허용 안내: 확인 못 함(코드와 단위 테스트만).
- 맥에서의 터미널 rauha 찾기(`~/.local/bin`·`/usr/local/bin`·`/opt/homebrew/bin`): 임시 폴더 테스트만, 확인 못 함.
- 문서·데스크톱 폴더 첫 접근 때 맥이 묻는 권한 창: 확인 못 함.
- 브라우저 연동(`ELECTRON_RUN_AS_NODE`로 띄우는 MCP)은 설치본에서 확인 못 함(Windows 개발 실행에서도 실제로 타 보지 않았어요).
- 실제 맥에서의 Claude 로그인(키체인)과 실제 일 맡기기: 확인 못 함.

Windows는 개발 PC에서 개발 실행으로 화면·허락 카드(가짜 팀)·레포·설정·규칙을 직접 확인했어요. Windows 설치 파일(.exe)을 실제로 설치해 실행한 것은 확인 못 함.
