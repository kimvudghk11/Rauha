# rauha 데스크톱 앱 설계

2026-11-08 · 상태: 초안(사용자 승인 전)
화면 시안: `.superpowers/brainstorm/26-1794067202/content/screens-v3.html` (커밋하지 않는 로컬 파일. 화면 12개를 눌러 볼 수 있다)

## 1. 왜 만드나

회사에서는 프로젝트 폴더 하나에 봐야 할 레포와 전용 문서 폴더를 모두 넣어 두고, 코드 작업과 문서 작업을 **동시에** 한다. 지금 rauha는 터미널 대화 모드다. 입력 하나를 보내면 그 일이 끝날 때까지 다음 입력이 줄을 선다(`ChatStore.queue`, `ChatSession.handle`이 한 번에 하나만 처리). 화면도 Claude Code 확장이나 Kiro보다 보기 어렵다.

그래서 터미널을 버리고 **설치형 데스크톱 프로그램**으로 옮긴다.
- 메인 칸에서 언제든 새 일을 내린다.
- 맡긴 일은 팀원이 각자 칸에서 진행하고, 그 모습이 캐릭터와 함께 보인다.
- 위험한 일만 정리된 화면을 보고 허락한다.
- 결국 VS Code를 열지 않아도 VS Code에서 하던 일을 다 할 수 있게 한다.

최상위 목표는 그대로다. **구독 한도를 아끼면서 최고 효율**을 낸다. 동시에 여러 일을 돌려도 호출 수와 모델 등급을 지금처럼 따진다.

## 2. 전체 범위와 순서

너무 커서 네 덩어리로 나누고, 하나씩 설계하고 만든다. 이 문서는 전체 방향과 **덩어리 1**의 설계다. 덩어리 2~4는 차례가 오면 따로 설계 문서를 쓴다.

| 순서 | 덩어리 | 내용 |
|---|---|---|
| 1 | 동시에 일하는 팀 | 데스크톱 틀, 채팅(메인 + 팀 방), 팀 상세(정리 화면), 허락과 알림, 규칙, 작업 폴더 읽기, 설정(계정·한도·알림), 첫 실행, 캐릭터 |
| 2 | VS Code 대신 | 코드 탭: 탐색기, 편집기(Monaco), git, 검색, 터미널 칸, 문제·출력 |
| 3 | 기록과 정보 저장 | 기록 탭(포트폴리오용 판단 기록, STAR로 뽑기), 내 AWS(S3)에 요약만 저장 |
| 4 | 할 일과 명령어 | 할 일 보드, 커스텀 명령어(템플릿·맡길 팀·단축키), 캐릭터 묶음 바꾸기와 내 이미지 올리기 |

## 3. 목표, 하지 않을 것, 실패로 볼 것

**목표**
- 메인 칸은 절대 막히지 않는다. 일을 넘긴 뒤 바로 다음 일을 받는다.
- 맡긴 일마다 지금 누가, 어느 단계에서, 무엇을 하는지 한눈에 보인다.
- 허락이 필요할 때 팀 화면에 정리가 다 되어 있어서, 로그를 뒤지지 않고 정할 수 있다.

**하지 않을 것 (이번 덩어리)**
- 코드 편집기, 할 일, 기록, 명령어 탭의 실제 기능. 탭 자리만 두고 "곧"으로 표시한다.
- macOS와 Linux 설치 파일. 회사 PC가 Windows라서 Windows를 먼저 만든다(빌더 판단 여지 있음).
- 캐릭터 커스텀.

**실패로 볼 것** (돌아가더라도 이러면 실패다)
- 기본 개발 작업마다 허락을 묻는다. git, aws 조회, 빌드·테스트, Chrome·Claude 웹 연동이 여기에 해당한다.
- 허락 창이 원본 명령 한 줄만 띄우고 정리가 없다.
- 동시 실행 때문에 한도가 눈에 띄게 빨리 닳는다. 미리 띄워 두는 호출이나 버려지는 호출이 늘어나는 경우다.
- 같은 레포를 두 일이 동시에 고쳐서 서로의 변경을 망친다.
- 인프라 점검을 시켰는데 aws configure 프로필로 aws CLI를 쓰지 않고 추측으로 답한다.
- 화면 어디든 돈(달러)이 보인다. 한도는 %로만 보여 준다.
- 구독 토큰을 읽거나 옮긴다. 계정 구분은 `CLAUDE_CONFIG_DIR`로만 한다.

## 4. 사용자가 정한 것

- **틀**: Electron. VS Code가 Electron이라 덩어리 2에서 Monaco·xterm.js·node-pty를 그대로 쓸 수 있고, Agent SDK와 `@rauha/core`가 Node에서 돌기 때문이다. Tauri는 Node를 옆에 따로 띄우고 Rust를 써야 해서 버렸다.
- **터미널 rauha(CLI)는 없앤다.** 프로그램 하나로 간다. 없애는 시점은 7절 질문 1.
- **색**: VS Code Dark Modern. 회사 PC가 게임 모드라 연한 파란 배경은 안 보인다. 하늘색은 Delfi 몸 색에만 쓴다. 토큰은 시안의 `:root`(`--bg #1f1f1f`, `--side #181818`, `--accent #0078d4` …)를 따른다.
- **배치**
  - 왼쪽에 세로 탭: 채팅, 코드, 할 일, 기록, 레포, 명령어, 규칙. 맨 아래에 설정.
  - 채팅 탭은 메인 칸과 팀 방으로 나뉘고, 사용자가 A(나란히)와 B(위아래)를 토글한다.
  - 아래 상태 줄에 세션·주간 한도 미니 막대가 있다.
- **캐릭터**
  - Delfi(하늘색 픽셀 돌고래, 팀장)와 친구들이다. **팀원마다 하나씩** 있다(지금 역할 22개).
  - Delfi는 시안 v3의 더 귀여운 그림(큰 눈 하이라이트, 볼터치, 웃는 입)을 쓴다.
  - **움직임이 많아야 한다.**
  - 캐릭터 묶음 바꾸기와 내 이미지 올리기는 덩어리 4에서 한다. 짱구 같은 남의 캐릭터는 기본으로 넣지 않는다. 사용자가 자기 이미지를 직접 구해 올리면 그 PC에만 저장된다.
- **작업 폴더**
  - 폴더 하나를 고르면 rauha가 그 안을 **전부 보고 알아서 판단**한다.
  - 레포, 문서 폴더, 기타가 섞여 있으므로 종류를 붙인다. 문서 폴더도 레포처럼 팀에 맡길 수 있다.
- **규칙 탭**
  - 내 규칙을 말로 적으면 Delfi가 정리해 넣는다.
  - 칸은 셋이다: **항상 지킬 것 / 묻지 않고 할 것 / 꼭 허락받을 것**.
  - 인프라 점검·조회는 **반드시 aws configure 프로필로 aws CLI를 쓴다.** 프로필은 요청에 맞는 것을 고른다. 지금 있는 기능(커밋 4cd69bd)을 그대로 쓴다.
- **묻지 않는 것**: git, aws 조회, 일반 개발 명령, Chrome·Claude 웹 연동.
- **허락받는 것**: 정말 위험하거나 점검이 필요한 일. 알림으로 알리고, 허락은 **각 팀 화면의 정리**를 보고 내린다. 정리 화면에 들어가는 것은 다음과 같다.
  - 공통: 한 줄 요약, 알아서 돌린 조회 명령, 알게 된 것, 하려는 일, 영향과 되돌리기
  - 코드: **diff**, 그리고 **main·qa 브랜치에 주는 영향**(충돌, 자동 배포, 몇 커밋 뒤처졌는지), 확인한 테스트
  - 인프라: **위험도**(환경, 계정·리전, 바뀌는 리소스, 영향 범위, 중단 여부, 비용 방향, 되돌리는 데 걸리는 시간, qa에 먼저 적용했는지)
- **화면 크기**: 회사에서 새 모니터를 따로 쓰므로, 그 모니터에 프로그램을 띄웠을 때 배치가 잘 나와야 한다. 창 크기와 배율이 바뀌면 팀 방 수와 칸 나눔이 다시 잡힌다. 창 위치와 크기는 모니터별로 기억한다(7절 질문 2).
- **설정**: 계정 바꾸기(`CLAUDE_CONFIG_DIR`), 지금 세션(5시간)과 주간(전체·Opus) 한도, 정보 저장(이름이 "AWS 연결"에서 바뀜), 알림.

## 5. 덩어리 1 설계

### 5.1 구성 요소

- **`packages/desktop`** (새 워크스페이스)
  - Electron main 프로세스가 `@rauha/core`를 돌린다.
  - 화면(renderer)은 Node에 직접 닿지 않는다. preload로 연 좁은 IPC 채널로만 main과 이야기한다(`contextIsolation` 켜기, `nodeIntegration` 끄기).
- **`@rauha/core`는 지금처럼** DDD 규칙(`docs/conventions/ddd-entity-dto.md`)을 따른다. 데스크톱 전용 로직도 규칙은 core의 엔티티·값 객체에 두고, desktop은 보여 주기와 IPC만 한다.
- **화면 라이브러리**: 빌더가 정한다. 조건은 세 가지다.
  - TypeScript
  - 덩어리 2에서 Monaco와 xterm.js를 붙이기 쉬울 것
  - 캐릭터 애니메이션을 매 프레임 다시 그려도 화면이 버벅이지 않을 것

### 5.2 메인과 맡긴 일: 동시에 돌리기

- **메인 칸(Delfi)** 은 라우팅과 짧은 답만 하고 바로 돌아온다. 일을 넘기면 "누구에게 넘겼다"는 카드만 남기고 다음 입력을 받는다.
- 넘긴 일 하나가 **작업(Job)** 하나다. 작업은 상태를 가진 도메인 엔티티다.
  - 상태: 대기, 진행, 허락 기다림, 내 선택 기다림, 끝, 멈춤
  - 진행 단계, 맡은 역할들, 대상 폴더도 작업이 가진다.
- 지금의 `ChatSession`은 한 세션이 상태(`turns`, `carried`, 비용 합산)를 하나만 들고 `handle`을 한 번에 하나씩 처리한다고 가정한다. 동시에 부르면 안 된다. 메인 대화와 각 작업이 상태를 나눠 갖도록 쪼갠다. 쪼개는 방법은 빌더가 정한다.
  - 메인 대화 기록은 라우팅 판단에 쓰이므로, 작업이 끝날 때 결과 요약을 메인 대화에 돌려준다.
  - 각 작업의 세부 대화(설계 대화, 질문)는 그 작업 화면에서 주고받는다.
- **같은 레포를 동시에 고치기**: 코드를 바꾸는 작업은 레포마다 **git worktree**에서 돈다(내 판단). 같은 레포에 두 번째로 쓰는 작업은 별도 worktree를 쓴다. 원래 브랜치로 합치는 건 허락 흐름(5.4)으로 한다. 읽기만 하는 작업은 원래 폴더를 그대로 읽는다.
- **동시 실행 개수 상한**: 기본 3(내 판단). 넘치면 대기로 두고 화면에 "대기 n"을 보인다.
- **한도**: 지금의 `session-budget`·`agent-sdk-plan-usage`를 그대로 쓴다. 동시 실행 중 세션 한도가 위험해지면 새 작업 시작을 미룬다.
- **팀 고르기**
  - 메인에는 팀 선택이 없다. 라우터가 지금처럼 알아서 고른다.
  - `@운영팀`처럼 팀을 직접 적으면 그 팀으로 보낸다(내 제안).
  - `@bridge-backend`처럼 레포·폴더를 적으면 대상 폴더를 정한다.
- **팀 방은 정해 두지 않는다.** 일하는 작업이 있는 부서·팀만 방이 생기고, 끝나면 잠시 "끝" 모습을 보였다가 사라진다. 회사에서 디자인 일이 없으면 디자인 방은 안 보인다.

### 5.3 팀 방과 팀 상세

- **팀 방(채팅 탭)에 보이는 것**
  - 캐릭터들과 말풍선(지금 하는 일 짧게)
  - 단계 막대: 그 작업 흐름의 단계(예: 설계 → 테스트 → 원인 찾기 → 고치기 → 리뷰)
  - 마지막 로그 한 줄과 걸린 시간
  - 상태 점: 진행 / 기다림 / 쉼
- 팀 방을 누르면 **팀 상세**가 열린다.
  - 기본은 **정리** 보기이고, 원본 로그는 탭을 눌러야 보인다.
  - 오른쪽에 진행 단계 타임라인과 바뀐 파일이 있다.
  - "멈추기"와 "메인으로" 버튼이 있다.
  - 작업이 내 선택을 기다리면(원인 후보 중 고르기 등) 선택지를 이 화면과 메인 칸에 함께 보인다.
- 정리 내용은 작업이 진행하며 쌓은 사실(이미 있는 `facts`, `decisions`, `assumptions`, 바뀐 파일)로 만든다. **정리만 하려고 모델 호출을 따로 하지 않는다.** 허락 요청 때 쓰는 요약은 허락을 요청하는 팀원이 그 호출 안에서 함께 내놓는다(schema에 필드 추가).

### 5.4 허락과 알림

- **판정**
  - 지금의 `tool-guard`를 넓혀서, 도구 호출마다 규칙 세 칸으로 판정한다.
  - "묻지 않고 할 것"에 맞으면 바로 실행한다.
  - "꼭 허락받을 것"에 맞으면 작업을 멈추고 허락을 요청한다.
  - 어디에도 안 맞으면 기본 위험 규칙으로 판정하고, 애매하면 허락 쪽으로 기운다.
- **기본 규칙** (처음 설치하면 들어 있고, 사용자가 고칠 수 있다)
  - 묻지 않음
    - git: push를 뺀 조회·브랜치·커밋. `git add -A`는 쓰지 않는다.
    - aws 조회: describe, list, get, logs, `configure list-profiles`
    - 빌드·테스트·린트·패키지 설치
    - Chrome·Claude 웹 연동으로 페이지 읽기
    - 작업 폴더 안 파일 읽기·쓰기(worktree 안)
  - 허락
    - 운영(prod) 리소스를 바꾸는 aws·terraform·kubectl 명령
    - 보호 브랜치(main·qa·release, 설정에서 고침)로 머지·push, force push
    - DB 쓰기·마이그레이션
    - 작업 폴더 밖 파일 바꾸기·지우기
- **허락 요청 하나는 화면 하나다.**
  - 앱 안 알림(오른쪽 아래 토스트)과 Windows 알림을 함께 띄운다. 누르면 그 팀 상세의 정리 보기로 간다.
  - 같은 작업의 허락 요청이 여러 개 쌓이면 하나로 묶어 보인다.
- **정리 보기의 종류별 내용**은 4절을 따른다.
  - 코드 diff는 바뀐 파일 목록과 나란히 보인다. 리뷰어 의견은 해당 줄 아래에 단다.
  - 브랜치 영향은 git으로 계산한다(`merge-base`, 충돌 시험 머지, ahead/behind). 모델 호출을 쓰지 않는다.
  - 자동 배포 여부는 레포의 CI 설정 파일을 읽어서 알아낸다. 못 찾으면 "모름"으로 쓴다.
  - 인프라 위험도 표는 운영 팀원이 허락 요청을 낼 때 함께 채운다. 비용은 방향(늘어남·줄어듦·같음)만 쓰고 금액은 쓰지 않는다.
- **버튼**: 한 번만 허락 / 이번 작업 동안 허락 / 다르게 해 줘(말로 고쳐 보내기) / 거절.

### 5.5 규칙

- 저장 범위는 셋이다: 전체(사용자), 이 작업 폴더, 특정 레포·폴더.
- 규칙을 말로 적으면 가장 가벼운 모델 한 번으로 칸과 범위를 정해 정리하고, 사용자가 보고 넣는다.
- "항상 지킬 것"은 해당 범위의 팀원 프롬프트에 들어간다. 이건 사용자의 규칙이라 넣는다. rauha 개발 스타일을 팀원 프롬프트에 넣지 말라는 CLAUDE.md 규칙과 다른 이야기다.
- 규칙 칸 판정은 5.4의 판정에 바로 쓰인다.

### 5.6 작업 폴더 읽기

- 고른 폴더 아래를 전부 훑는다.
  - 생성물 폴더는 들어가지 않는다: `node_modules`, `dist`, `build`, `.venv`, `.next`, `target` 등. `.gitignore`도 따른다.
  - 폴더마다 종류를 붙인다: 레포(`.git`), 문서(md·pdf·docx가 대부분), 기타.
- 처음에는 구조와 종류만 본다. 파일 내용은 팀원이 그 일을 맡았을 때 필요한 만큼만 읽는다. 지금의 저장소 지식과 `surveyor`를 그대로 쓴다.
- 폴더를 감시해서 새 레포나 폴더가 생기면 목록에 반영한다. "다시 읽기"는 보조 버튼이다.
- 레포 탭(목록, 브랜치, 상태, 지금 작업 중인 팀, 레포끼리 기대는 순서)은 덩어리 1에 넣는다. 작업 대상을 고르는 데 필요해서다.

### 5.7 캐릭터

- 그림체는 지금 `mascot.ts`의 Delfi와 같은 픽셀 그림이다. 색은 지금 역할 색(`ROLE_COLOR`) 계열을 쓰되 다크 바탕에서 보이게 맞춘다.
- 22개 역할마다 하나씩 그린다. 이름과 동물은 빌더가 제안하고 사용자가 고른다. 시안에서는 토비(거북), 집게(게), 무니(문어), 뽀글(복어)을 제안했다.
- **움직임을 많이** 넣는다. 상태마다 다른 움직임을 둔다.
  - 일함: 통통 튀기, 말풍선 타자
  - 생각: 머리 위 물음표·전구
  - 기다림·허락 기다림: 손 흔들기, 느낌표
  - 끝: 반짝이, 점프
  - 멈춤: 땀방울
  - 쉼: 졸기(z)
  - 상태와 상관없이: 가끔 눈 깜빡임, 방 안을 조금씩 걸어 다니기
- 캐릭터를 이미지가 아니라 데이터(픽셀 격자와 프레임)로 두면 덩어리 4의 캐릭터 묶음 바꾸기가 쉽다.
- 덩어리 4의 내 이미지 올리기를 위해, 화면에서 캐릭터를 그리는 곳은 "역할 → 그림" 한 곳으로 모은다.

### 5.8 첫 실행

순서: 작업 폴더 고르기 → 이 폴더에서 일해도 될지 허락 → Claude 계정 고르기(이미 로그인된 Claude Code 설정 폴더 중에서) → 정보 저장(건너뛰어도 됨. 덩어리 3 전까지는 자리만 둔다).

### 5.9 설정 (덩어리 1에서 만드는 것)

- **계정·한도**
  - 계정 목록과 바꾸기. 계정 하나 = `CLAUDE_CONFIG_DIR` 하나다.
  - 지금 세션, 이번 주 전체, 이번 주 Opus 사용률과 초기화 시각
  - 색: 70% 노랑, 90% 빨강
- **알림**: 내 선택 기다림, 작업 끝, 한도 90%, 단계 넘어감(기본 꺼짐)
- **화면**: A/B 배치
- **권한**: 보호 브랜치 목록, 동시 실행 개수
- **정보 저장, 캐릭터**: "곧"

## 7. 사용자에게 남은 질문

1. **터미널 rauha를 언제 지우나.** 덩어리 1이 끝나면 바로 지울지, 아니면 지금 CLI에만 있는 명령(`/routine`, `/learn`, `/company`, `/guide`, `/review`, `/retry`, `/copy`, `/update`)을 데스크톱으로 다 옮긴 뒤에 지울지.
2. **새 모니터의 모양.** 가로인지 세로인지, 해상도와 Windows 배율(%), 그리고 프로그램을 그 모니터에 꽉 채워 띄우는지 반만 띄우는지.
3. **회사 PC에 설치가 되나.** 서명 안 된 설치 파일(.exe)을 회사 PC에서 설치할 수 있는지. 막히면 설치 없이 폴더째 실행하는 방식으로 바꿔야 한다.
